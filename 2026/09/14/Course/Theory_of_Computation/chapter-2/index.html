Use DFA and NFA to refer to deterministic finite automata and nondeterministic finite automata, respectively.

1 Deterministic Finite Automata

A finite automaton receives string input and passes it in the form of an input tape, after which it outputs only an indication of whether the input is considered acceptable. More details about the operation of finite automata (more precisely, deterministic finite automata, DFA) are as follows:

The input tape is divided into individual cells, each cell representing a single symbol in the string.

The main part of the entire machine can be viewed as a "black box" that is in one of its internal states (state) at any given moment (the total number of states is finite).

This "black box" is called a finite control, and with the help of a movable reading head, it senses the symbol written at any position on the input tape.

Initially, the reading head is placed at the leftmost cell of the tape, and the finite control is set to the initial state.

At fixed intervals, the automaton reads one symbol from the input tape, then enters a new state based on the current state and the symbol read; after reading, the reading head moves one cell to the right.

The above process repeats until the end of the input string is reached, at which point the automaton indicates whether the content read is accepted or not through the state it is in when it finishes. If it stops in a state belonging to a set of final states, then the input string is regarded as accepted.

The language accepted by the machine is the set of strings it accepts.

1.1 DFA Minimization

For any language that can be represented by a DFA, there exists a unique minimized DFA. The steps for minimizing a DFA are:

  1. Remove unreachable states.

  2. Merge equivalent states: partition the states into several equivalence classes.

    • Accepting states and non-accepting states are not equivalent.

    • Two states that transition to different equivalence classes on some input symbol are not equivalent.

    • Starting from {K−F,F}\{K - F, F\}{K−F,F}, repeatedly partition each tentative equivalence class until no further partitioning is possible.

2 Nondeterministic Finite Automata

Nondeterminism in an automaton means that the change of state depends only in part on the current state and the input symbol. That is, for a given current state and input symbol, multiple possible next states are allowed; the automaton may choose any one of these legal next states, and this choice is not affected by the model.

This kind of nondeterminism is a notational generalization of finite-state machines and can greatly simplify the description of automata. Moreover, as we will see later: every nondeterministic finite automaton is equivalent to some deterministic finite automaton.

In addition, we allow arrows labeled with the empty string eee on an NFA, which lets the automaton make state transitions without reading any input.

The formal definition of an NFA is as follows:

A nondeterministic finite automaton (NFA) is a five-tuple M=(K,Σ,Δ,s,F)M = (K, \Sigma, \Delta, s, F)M=(K,Σ,Δ,s,F), where:

  • KKK: a finite set of states

  • Σ\SigmaΣ: the alphabet

  • s∈Ks \in Ks∈K: the initial state

  • F⊆KF \subseteq KF⊆K: the set of final states

  • Δ\DeltaΔ: the transition relation, a subset of K×(Σ∪{e})×KK \times (\Sigma \cup \{e\}) \times KK×(Σ∪{e})×K

3 Regular Expressions

The central problem of computation theory is to represent languages through finite specifications. Obviously, finite languages can be exhaustively enumerated, so we only need to consider the problem of infinite languages.

One conclusion is that no matter how powerful the method used to represent languages is, only countably many languages can be represented, as long as the representation itself is also finite. Therefore, those uncountably many languages naturally cannot be represented using finite representations.

Consider the concept of an expression, namely a string of symbols that describes how a language is constructed through the operations introduced earlier. Among these, a regular expression over Σ∗\Sigma^*Σ∗ is a string over the alphabet Σ∪{(,),⊘,U,∗}\Sigma \cup \{(, ), \oslash, \mathsf{U}, *\}Σ∪{(,),⊘,U,∗}, obtained in the following way:

  • ⊘\oslash⊘ and every member of Σ\SigmaΣ are regular expressions

  • If α,β\alpha, \betaα,β are both regular expressions, then (αβ)(\alpha \beta)(αβ) is also a regular expression

  • If α,β\alpha, \betaα,β are both regular expressions, then (αUβ)(\alpha \mathsf{U} \beta)(αUβ) is also a regular expression

  • If α\alphaα is a regular expression, then α∗\alpha^*α∗ is also a regular expression

  • Only strings satisfying all four conditions above are regular expressions; otherwise, they are not

The relationship between regular expressions and the languages they represent is established by the function L\mathcal{L}L, such that if α\alphaα is any regular expression, then L(α)\mathcal{L}(\alpha)L(α) is the language represented by α\alphaα. The specific definition of the function L\mathcal{L}L is as follows:

Every language that can be expressed by one regular expression can be represented by infinitely many other regular expressions. We usually ignore redundant parentheses ((,)(, )(,)) in regular expressions.

4 Regular Languages

Another definition of a regular language is a language accepted by an FA (DFA/NFA). Next, we prove the closure properties of languages accepted by FAs:

The class of languages accepted by finite automata is closed under the following operations: union, concatenation, Kleene star, complement, and intersection.

A language is regular if and only if it is accepted by a finite automaton.

5 Languages that Are and Are Not Regular

Although we currently have powerful techniques capable of proving that a language is regular, we have not yet shown how to determine that a language is not regular. Below are two properties possessed by regular languages but not possessed by some non-regular languages:

  • When scanning a string from left to right, the amount of memory required to ultimately determine whether the string belongs to a certain language must be finite, fixed in advance, and dependent on the language itself, not on the particular input string. For example, we can determine that {anbn:n≥0}\{a^n b^n: n \ge 0\}{anbn:n≥0} is not regular, because it is impossible to construct a finite-state device that, upon reaching the boundary between aaa and bbb, accurately remembers how many aaa it has seen and compares this with the number of bbb.

  • A regular language with an infinite number of strings is represented by an automaton with loops and by a regular expression containing the Kleene star. Such languages necessarily possess infinite subsets with some kind of simple repetitive structure, arising from the Kleene star in the corresponding regular expression or from loops in the state diagram of a finite automaton. For example, the set {an:n>1 is a prime}\{a^n: n > 1 \text{ is a prime}\}{an:n>1 is a prime} is not regular, because there is no simple periodicity in the set of prime numbers.

These intuitive ideas, although accurate, are not precise enough for use in formal proofs. We will now prove a theorem that captures part of this intuition and easily derives the non-regularity of certain languages as a direct consequence.

5.1 Pumping theorem

Let LLL be a regular language. There exists an integer n≥1n \ge 1n≥1 (the pump length) such that any string w∈Lw \in Lw∈L (∣w∣≥n|w| \ge n∣w∣≥n) can be rewritten as w=xyzw = xyzw=xyz, satisfying y≠e,∣xy∣≤ny \ne e, |xy| \le ny=e,∣xy∣≤n and xyiz∈L,i≥0xy^iz \in L, i \ge 0xyiz∈L,i≥0.

The pumping theorem can be regarded as a necessary but not sufficient condition for proving that a language is regular. We often use it to prove that a language is not regular.

5.2 Summary: Deciding regular languages

There is no general method for determining whether an arbitrary language is regular.

Proving that a language is regular

  1. The language is finite.

  2. Construct an FA that accepts the language.

  3. Construct a regular expression that generates the language.

  4. Closure properties of regular languages.

Proving that a language is not regular

  1. Pumping theorem

  2. Proof by contradiction

    • There is no FA that accepts the language.

    • Closure properties of regular languages (a commonly used technique is to take the intersection of a known regular language with the language given in the problem; if the intersection is not regular, then the language given in the problem must not be regular (the converse is not necessarily true)).
