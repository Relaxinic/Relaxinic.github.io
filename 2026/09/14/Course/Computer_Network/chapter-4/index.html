The main task of the network layer is to transmit packets from the source host to the destination host through multiple networks and multiple links. This task can be divided into two important functions: packet forwarding and routing.

The network layer provides two types of services to the upper layer:

Connection-oriented virtual circuit service

  • The core idea is that "reliable communication should be guaranteed by the network itself."

  • A connection called a virtual circuit (VC) must first be established in the network layer to ensure all network resources required by both communicating parties.

  • The two communicating parties send packets along the established virtual circuit. A virtual circuit indicates that this is a logical connection; packets are transmitted along this logical connection in a store-and-forward manner, rather than establishing a true physical connection. The header of a packet uses the complete destination host address only during the connection establishment phase; afterward, the header of each packet only needs to carry a virtual circuit identifier.

  • After communication ends, the previously established virtual circuit needs to be released.

  • If this communication method also uses a reliable transport network protocol, the sent packets can ultimately arrive at the receiver correctly (error-free, in order, without loss, and without duplication).

  • Many wide area packet-switched networks use the connection-oriented virtual circuit service, but the Internet uses the connectionless datagram service.

Connectionless datagram service

  • The core idea is that "reliable communication should be guaranteed by the user hosts."

  • There is no need to establish a network layer connection, so after communication ends there is no connection to release.

  • Each packet may take a different path, so the header of each packet must carry the complete address of the destination host.

  • Packets transmitted by this communication method may have bit errors, be lost, duplicated, or arrive out of order.

  • Because the network itself does not provide end-to-end reliable transmission services, routers in the network can be made relatively simple, greatly reducing network cost.

  • In addition, this design philosophy operates flexibly and can adapt to a variety of applications.

1 Internet Protocol

The Internet Protocol (IP) is the core protocol in the network layer of the TCP/IP architecture.

1.1 IPv4 Addresses and Their Addressing Methods

An IPv4 address is a globally unique 32-bit identifier assigned to each interface of every host (or router) on the Internet, and it is allocated by the Internet Corporation for Assigned Names and Numbers (ICANN).

IPv4 addresses use dotted-decimal notation to make them easier for users to use.

The addressing method initially adopted was classful addressing. An IPv4 address can be split into two parts:

  • Network number: identifies the network to which the interface of the host (or router) is connected. Within the same network, the network numbers of the IPv4 addresses of the interfaces of different hosts (or routers) must be the same, indicating that they belong to the same network.

  • Host number: identifies the interface of the host (or router). Within the same network, the host numbers of the IPv4 addresses of the interfaces of different hosts (or routers) must be different so as to distinguish the interfaces of the hosts (or routers).

There are 5 classes of IPv4 addresses:

  • Class A, Class B, and Class C addresses are all unicast addresses, and only unicast addresses can be assigned to the interfaces of hosts (or routers) in a network.

  • An address whose host number is all 0s is a network address and cannot be assigned to the interfaces of hosts (or routers).

  • An address whose host number is all 1s is a broadcast address and cannot be assigned to the interfaces of hosts (or routers).

As more small and medium-sized networks joined the Internet, the shortcomings of the IPv4 classful addressing method—being insufficiently flexible and easily causing a large amount of waste of IPv4 address resources—became exposed. Therefore, the subnetting addressing method was introduced to improve it.

A subnet mask can indicate how many bits have been borrowed from the host number portion of a classful IPv4 address as the subnet number. Similar to an IPv4 address, a subnet mask is also composed of 32 bits.

  • Multiple consecutive 1 bits starting from the left correspond to the network number and subnet number in the IPv4 address.

  • The subsequent multiple consecutive 0 bits correspond to the host number in the IPv4 address.

By performing a bitwise logical AND operation on the subnetted IPv4 address and the corresponding subnet mask, the network address of the subnet to which the IPv4 address belongs can be obtained.

1

The default subnet mask refers to the subnet mask used when no subnetting is performed.

The address mask used by the classless addressing method is similar to the subnet mask used for subnetting, and consists of 32 bits. A sequence of consecutive 1 bits starting from the left corresponds to the network prefix in the IPv4 address, and the following sequence of consecutive 0 bits corresponds to the host number in the IPv4 address.

For simplicity, a slash / can be appended after a classless addressing address, followed by the number of bits occupied by the network prefix. This notation is called slash notation.

In fact, classless inter-domain routing (CIDR) groups multiple consecutive classless IPv4 addresses with the same network prefix into a CIDR address block. As long as any one of the addresses is known, all of the following details of the address block can be determined: the smallest address in the address block, the largest address in the address block, the number of addresses in the address block, the number of networks of a certain class (Class A, Class B, Class C) aggregated in the address block, and the address mask.

Using the classless addressing method, CIDR address blocks of an appropriate size can be allocated according to customer needs, so the IPv4 address space can be allocated more efficiently.

Another benefit of using the classless addressing method is route aggregation (also called constructing a supernet).

The longer the network prefix, the smaller the address block, and the more specific the route.

If a router finds that multiple routing entries match when looking up the table to forward a packet, it selects the routing entry with the longest network prefix. This is called longest prefix matching, because such a route is more specific.

1.2 IPv4 address and MAC address

Changes in IPv4 addresses and MAC addresses during datagram transmission:

  • During packet transmission, the source IP address and destination IP address of the packet remain unchanged.

  • During packet transmission, the source MAC address and destination MAC address of the packet change link by link (or network by network).

The result of table lookup forwarding can indicate the IP address of the next-hop router for the IP datagram, but it cannot indicate the MAC address corresponding to that IP address. Therefore, when the IP datagram is encapsulated into a frame at the data link layer, the destination MAC address field in the frame header cannot be filled in. This problem needs to be solved using the Address Resolution Protocol in the network layer.

1.3 Address Resolution Protocol (ARP)

The Address Resolution Protocol (ARP) is used to resolve the IP addresses of hosts within a local area network to their corresponding MAC physical addresses.

The record types in the ARP cache table are divided into:

  • Dynamic: automatically obtained through ARP, with a default lifetime of 2 min

  • Static: manually configured, with lifetimes that vary across operating systems; for example, they may not exist after a system restart or may remain valid after a system restart

The correspondence between IP addresses and MAC addresses in the ARP cache table is not permanent, for example, when a host replaces its network card with a new one

Since the main purpose of the ARP protocol is to resolve the IP addresses used at the network layer into the MAC addresses used at the data link layer, some textbooks classify the ARP protocol as belonging to the network layer, while others classify it as belonging to the data link layer; both approaches are acceptable

In addition to the ARP request messages and response messages introduced in this lesson, the ARP protocol also has other types of messages, such as gratuitous ARP, which is used to check for IP address conflicts

Since the ARP protocol was formulated very early (November 1982), network security issues were not taken into consideration at the time; therefore, the ARP protocol has no security verification mechanism and is subject to problems such as ARP spoofing and attacks

1.4 Header Format of IPv4 Datagrams

The header format and contents of an IPv4 datagram are the foundation for implementing the various functions of the IPv4 protocol.

In the TCP/IP standards, various data formats are often described in units of 32 bits (i.e., 4 bytes).

The fixed part refers to the part that every IPv4 datagram must contain.

The header of some IPv4 datagrams, in addition to containing the 20-byte fixed part, also contains some optional fields to add functionality to the IPv4 datagram.

The following describes the meaning and functions of each field or combination of fields in the IPv4 datagram header:

Version: The length is 4 bits, used to indicate the version of the IP protocol.

  • The versions of the IP protocol used by both communicating parties must be the same.

  • The version number of the IP protocol currently widely used is 4 (i.e., IPv4).

Internet header length (IHL):

  • The length is 4 bits. The value of this field is in units of 4 bytes and is used to indicate the header length of an IPv4 datagram.

  • The minimum value is 0101 in binary, i.e., 5 in decimal, which, multiplied by the 4-byte unit, indicates that the IPv4 datagram header contains only the 20-byte fixed part.

  • The maximum value is 1111 in binary, i.e., 15 in decimal, which, multiplied by the 4-byte unit, indicates that the IPv4 datagram header contains the 20-byte fixed part and a variable part of up to 40 bytes.

Differentiated services:

  • The length is 8 bits. Different values of this field can be used to provide different levels of quality of service.

  • In the old standard, this field was called type of service, but in practice it was never used; in 1998, the IETF renamed this field differentiated services.

  • This field takes effect only when differentiated services are used; under normal circumstances, this field is not used.

Total length:

  • The length is 16 bits. The value of this field is in bytes and is used to indicate the length of the IPv4 datagram (header length + payload length).

  • The maximum value is 16 binary 1s, i.e., 65535 in decimal (IPv4 datagrams of such length are rarely transmitted).

IPv4 datagram fragmentation: When the length of an IPv4 datagram exceeds the MTU (maximum transmission unit), it cannot be encapsulated into a frame, and the original IPv4 datagram needs to be fragmented into several smaller IPv4 datagrams.

  • Identification: The length is 16 bits. All fragments of the same IPv4 datagram should have the same identification. The IP software maintains a counter. Each time an IPv4 datagram is generated, the counter value is incremented by 1, and this value is assigned to the identification field.

  • Flag

    • Lowest bit (more fragment, MF): MF=1 indicates that there are more fragments after this fragment; MF=0 indicates that there are no more fragments after this fragment.

    • Middle bit (don't fragment, DF): DF=1 indicates that fragmentation is not allowed; DF=0 indicates that fragmentation is allowed. The highest bit is a reserved bit and must be set to 0.

Time to Live (TTL)

  • It is 8 bits long, and its value was initially in seconds, so the maximum time to live of an IPv4 datagram was initially 255 s; when a router forwards an IPv4 datagram, it subtracts from the value of this field in its header the time the datagram spent on the router, and if the result is not 0, it forwards it; otherwise, it discards it. Later, it was changed to use hop count as the unit.

  • Purpose: to prevent incorrectly routed IPv4 datagrams from circulating endlessly in the Internet.

Protocol:

  • It is 8 bits long and is used to indicate what kind of PDU the data payload of the IPv4 datagram is.

  • Some commonly used protocols and their corresponding protocol field values: ICMP: 1 / IGMP: 2 / TCP: 6 / UDP: 17 / IPv6: 41 / OSPF: 89

Header checksum:

  • It is 16 bits long and is used to detect whether errors have occurred in the header of an IPv4 datagram during transmission.

  • Each time an IPv4 datagram passes through a router, the values of some fields in its header (such as TTL, flags, and fragment offset) may change, so the router must recalculate the header checksum.

  • Calculation method:

The above checksum calculation method is used not only for the IP protocol but also for UDP and TCP at the transport layer, and is often called the Internet checksum; although the error-detection performance of this checksum is inferior to CRC, it is easier to implement in software.

Source address: It is 32 bits long and is used to fill in the IPv4 address of the source host sending the IPv4 datagram.

Destination address: It is 32 bits long and is used to fill in the IPv4 address of the destination host receiving the IPv4 datagram.

Fragment offset: It is 13 bits long, and the value of this field is in units of 8 bytes; it is used to indicate how far the data payload of a fragmented IPv4 datagram is offset from its position in the original IPv4 datagram.

Options:

  • The length ranges from 1 byte to 40 bytes, and it is used to support functions such as troubleshooting, measurement, and security measures.

  • Although the options field increases the functionality of IPv4 datagrams, it also makes the header length of IPv4 datagrams variable, which increases the overhead for every router in the Internet to process IPv4 datagrams.

  • In practice, this field is rarely used.

Padding: It is used to ensure that the header length of an IPv4 datagram is an integer multiple of 4 bytes, using all-zero padding.

2 Static Routing Configuration

Static route configuration refers to users or network operations personnel using the relevant commands of a router to manually configure the routing table for the router. This approach is simple and has low overhead, but it cannot promptly adapt to changes in network conditions (traffic, topology, etc.), so it is generally used only in small-scale networks.

Performing static route configuration requires careful consideration and cautious operation; otherwise, the following problems may occur:

  • Incorrect configuration of route entries, which may even lead to routing loops

  • Summarized route entries may introduce nonexistent networks

3 Internet Routing Protocols

3.1 Classification of Routing

Static routing (described in detail earlier)

Dynamic routing

  • Routers automatically obtain routing information through routing protocols

  • Dynamic routing is more complex and has higher overhead, but it can better adapt to changes in network conditions

  • Dynamic routing is suitable for large-scale networks

3.2 Hierarchical Routing Protocols

The Internet is the largest Internet in the world. The routing selection protocol it adopts has the following three main characteristics:

Adaptive: The Internet adopts dynamic routing selection, which can better adapt to changes in network status.

Distributed: Routers on the Internet jointly complete the acquisition and update of routing information through mutual information interaction.

Hierarchy: Divide the entire Internet into many smaller autonomous systems (AS). Different types of routing selection protocols are adopted inside and outside the autonomous system, and routing selection is carried out separately.

Exterior Gateway Protocol (EGP) and Interior Gateway Protocol (IGP) are merely category names for routing protocols, not specific routing protocols.

The term "gateway" is used in the names Exterior Gateway Protocol and Interior Gateway Protocol because early RFC documents of the Internet did not use the term "router" but instead used the term "gateway."

3.3 Routing Information Protocol (RIP)

Routing Information Protocol (RIP) was one of the first interior gateway protocols to be widely used. It is a distance-vector protocol. Every router in an AS maintains a record of its distance to every other network in the AS; this set of distances is called a distance vector (D-V).

RIP uses hop count to measure the distance to a destination network:

  • The distance from a router to a directly connected network is defined as 1.

  • The distance to a network that is not directly connected is the number of routers passed through plus 1.

  • The maximum RIP distance is 15, and a distance of 16 means unreachable. Therefore, RIP is suitable only for small internetworks.

RIP considers a good route to be a short route, that is, one passing through the fewest routers. When several routes to the same destination have equal RIP distances, equal-cost load balancing can distribute traffic evenly among them.

RIP has three important characteristics:

  • With whom information is exchanged: only neighboring routers.

  • What information is exchanged: the router's own routing table. Each entry contains the destination network, the shortest RIP distance, and the next-hop router.

  • When information is exchanged: periodically, and through triggered updates. When the topology changes, routers promptly advertise the updated routing information to their neighbors to accelerate convergence.

The basic operation is as follows:

  • When a router starts, it knows only that its RIP distance to each directly connected network is 1.

  • Each router periodically exchanges and updates routing information with its neighbors.

  • After several exchanges and updates, each router knows the shortest distance and next hop to every network in the AS. This is called convergence.

Reasons for updating or retaining the entries:

  • N2: the next hop is unchanged, so the latest information must replace the old entry.

  • N3: a new destination network has been discovered, so add the entry.

  • N6: the next hop differs and the new route is better, so update the entry.

  • N8: the next hop differs and the RIP distance is equal, so add the route for equal-cost load balancing.

  • N9: the next hop differs and the new route is worse, so retain the old entry.

Besides these update rules, the algorithm includes timing parameters. A router sends routing updates to all neighbors approximately every 30 seconds. If an entry receives no update for 180 seconds by default, it is marked invalid by setting its RIP distance to 16. If no update arrives after a further interval, such as 120 seconds, the entry is deleted.

RIP has the problem that bad news travels slowly, also called the routing-loop or count-to-infinity problem.

Measures to reduce its impact include:

  • Limit the maximum RIP distance to 15, with 16 indicating unreachable.

  • Send triggered updates immediately when the routing table changes, rather than relying only on periodic updates.

  • Split horizon: never advertise a route back to the neighbor from which it was learned.

  • Poisoned reverse: a route may be advertised back to the neighbor from which it was learned, but its distance is set to infinity, thereby poisoning the route.

RIPv2, published in November 1998 in RFC 2453, became an Internet standard. Compared with RIPv1, it supports variable-length subnet masks and CIDR, provides a simple authentication procedure, and supports multicast.

RIP messages are encapsulated using UDP and use UDP port 520. From the perspective of encapsulation, RIP belongs to the application layer of the TCP/IP architecture. Its central function, routing, belongs to the network layer.

Advantages:

  • Simple implementation and low router overhead.

  • Updates announcing a shorter route propagate quickly: good news travels fast.

Disadvantages:

  • The maximum distance of 15 limits the size of an AS.

  • Neighbors exchange complete routing tables, so overhead increases with network size.

  • Slow propagation of bad news leads to long convergence times.

3.4 Open Shortest Path First Protocol (OSPF)

Open Shortest Path First (OSPF) was developed to overcome RIP's disadvantages. It is a link-state protocol. Open means that it is publicly published rather than controlled by a particular vendor; shortest path first refers to its use of Dijkstra's shortest-path algorithm.

Link-state information describes which routers are adjacent to the current router and the costs of the corresponding links. Costs can represent expense, distance, delay, bandwidth, and other factors determined by network administrators. Link-state information and the shortest-path algorithm together prevent routing loops. OSPF does not impose RIP's network-size limit and provides efficient updates and fast convergence.

Neighboring routers establish and maintain neighbor relationships by exchanging hello packets. These are encapsulated directly in IP datagrams sent to multicast address 224.0.0.5. The IP protocol field is 89, indicating an OSPF payload. Hello packets are sent every 10 seconds; if none is received from a neighbor for 40 seconds, that neighbor is considered unreachable. Each router maintains a neighbor table.

Each OSPF router generates link-state advertisements (LSAs) containing the link states of its directly connected networks and neighboring routers. LSAs are encapsulated in link-state update (LSU) packets and distributed by reliable flooding.

In flooding, a router sends an LSU to all its neighbors. Each receiving router forwards it to its other neighbors, excluding the upstream router. Reliability means that received updates are acknowledged. Duplicate updates need not be forwarded again, but must still be acknowledged.

Every OSPF router maintains a link-state database (LSDB). As routers flood LSUs carrying their LSAs, the databases eventually become consistent.

Each router performs shortest-path-first calculations using its LSDB, determines its shortest paths to other routers, and constructs its routing table.

OSPF packet types:

  • Hello: discovers neighbors and maintains their reachability.

  • Database description: gives a neighbor summary information about all link-state entries in the sender's database.

  • Link-state request: requests detailed information about particular link-state entries.

  • Link-state update: floods link-state information to update the system.

  • Link-state acknowledgment: acknowledges link-state updates.

To reduce the number of hello and link-state update exchanges, OSPF elects a designated router (DR) and a backup designated router (BDR). To support very large networks, OSPF divides an AS into smaller areas. Flooding of link-state information is confined to each area rather than the entire AS, reducing overall traffic. An area should not be too large; it should generally contain no more than 200 routers. 3.5 Border Gateway Protocol (BGP)

BGP is an application-layer protocol. It is discussed here because its purpose is closely related to the network layer, even though its mechanisms have clear application-layer characteristics.

Border Gateway Protocol (BGP) belongs to the EGP category and provides routing between ASes. Different ASes may measure route costs differently, so a uniform cost metric cannot be used to find a globally optimal route. Inter-AS routing must also consider political, economic, security, and other policies configured by network administrators; these policies are not themselves routing protocols. BGP seeks a reasonably good route that reaches the destination without loops, rather than a globally optimal route.

When configuring BGP, an AS administrator selects at least one router as a BGP speaker. Two speakers are generally connected through a shared network, and speakers are often BGP border routers. Speakers that exchange routing information over a TCP connection are called neighbors or peers.

A BGP speaker must also run its AS's IGP, such as RIP or OSPF. Speakers exchange network-reachability information: the sequence of ASes traversed to reach a network. They apply their policies to the received information and choose suitable routes, constructing a tree-like, loop-free AS connectivity graph.

BGP is suitable for the Internet's multilevel structure.

BGP-4 is specified in RFC 4271, which defines four message types:

  • OPEN: establishes a relationship with a neighboring speaker and initializes communication.

  • KEEPALIVE: periodically confirms a neighbor's connectivity.

  • UPDATE: advertises a route and lists routes to withdraw.

  • NOTIFICATION: reports detected errors.

3.6 Basic Operation of a Router

A router is a special-purpose computer with multiple input and output ports. Its task is to forward packets.

  • A routing table generally maps destination networks to next hops and is organized to optimize calculations following topology changes.

  • A forwarding table is derived from the routing table and should optimize lookups.

A router may run no routing protocol when all routes are static, one protocol in a small or medium-sized network, or several protocols at a network boundary. Switching-fabric speed is critical to forwarding performance. The three basic implementations use memory, a bus, or an interconnection network; the achievable forwarding rate increases in that order.

4 Internet Control Message Protocol (ICMP)

The network layer of the TCP/IP architecture uses Internet Control Message Protocol (ICMP) to forward IP datagrams more effectively and improve their chances of successful delivery. Hosts and routers use it to send error reports and queries. ICMP messages are encapsulated in IP datagrams.

4.1 Message Types

Error-reporting messages report problems to hosts or routers.

Destination unreachable: sent to the source when a router or host cannot deliver an IP datagram. The code field further distinguishes 13 cases, including destination network, host, protocol, or port unreachable, and destination network or host unknown.

Source quench: sent when a router or host discards a datagram because of congestion, informing the source that it should reduce its sending rate.

Time exceeded: when a router receives a datagram addressed elsewhere, it subtracts 1 from the TTL. If the result is nonzero, it forwards the datagram. If the result is zero, it discards the datagram and sends a time-exceeded message to the source. A destination also discards the fragments already received and sends a time-exceeded message if all fragments fail to arrive within the prescribed reassembly time.

Parameter problem: when a router or destination host uses the header checksum to discover that a transmission error has occurred in the received IP datagram's header, it discards the datagram and sends this message to the source.

Redirect: a router informs a host that future datagrams should be sent to another router to reach the destination through a better route.

ICMP error reports should not be sent:

  • In response to another error-reporting message.

  • For fragments other than the first fragment of an IP datagram.

  • For IP datagrams with multicast addresses.

  • For IP datagrams with special addresses, such as 127.0.0.0 or 0.0.0.0.

Query messages ask hosts or routers for information.

  • Echo request and reply: a host or router sends a request to a particular destination, which returns an ICMP echo reply. These messages test reachability and obtain information about the destination's status.

  • Timestamp request and reply: request the current date and time from a host or router. An ICMP timestamp reply contains a 32-bit field whose integer value represents the number of seconds elapsed since January 1, 1900. These messages are used for clock synchronization and time measurement.

4.2 Typical Applications

Packet Internet Groper (PING) tests connectivity between hosts or routers. It is an example of an application directly using network-layer ICMP and bypassing the transport layer. It uses echo requests and replies. Some hosts and servers ignore incoming echo requests to guard against malicious attacks.

Traceroute discovers the routers traversed from a source to a destination. Its command and implementation differ by operating system:

  • UNIX traceroute uses UDP at the transport layer and ICMP error-reporting messages at the network layer.

  • Windows tracert directly uses network-layer ICMP, including echo request/reply messages and error reports.

5 Virtual Private Networks and Network Address Translation

5.1 Virtual Private Network (VPN)

A virtual private network (VPN) uses the public Internet as the communication medium between an organization's private networks. The organization may independently assign private IP addresses to its internal hosts. These addresses are valid only internally and do not require an application to an Internet address-management organization.

RFC 1918 reserves three CIDR blocks for private addressing:

  • 10.0.0.0–10.255.255.255, or 10/8.

  • 172.16.0.0–172.31.255.255, or 172.16/12.

  • 192.168.0.0–192.168.255.255, or 192.168/16.

Internet routers do not forward datagrams destined for private addresses; ISPs configure their routers to enforce this. Although an IP datagram may traverse multiple networks and routers, the logical connection can appear to be a direct point-to-point link. This is called IP tunneling.

  • Intranet VPN: connects the internal networks of different departments in one organization.

  • Extranet VPN: allows an external organization, usually a partner, to join an organization's VPN.

  • Remote-access VPN: an employee working elsewhere connects to the Internet and runs VPN software to establish a tunnel between the employee's PC and the company, allowing access to private-network resources.

5.2 Network Address Translation (NAT)

Network address translation (NAT), proposed in 1994, alleviates IPv4 address-space exhaustion. It allows many users of internal private addresses to share a small number of external global addresses when accessing Internet hosts and resources.

The router connecting the private network to the Internet must run NAT software and have at least one valid external global IP address, IPG\mathrm{IP}_GIPG​. When private hosts communicate with the Internet, the NAT router translates their internal addresses into IPG\mathrm{IP}_GIPG​.

Combining NAT with transport-layer port numbers gives network address and port translation (NAPT). Many internal hosts can then share one global IP address and communicate simultaneously with different Internet hosts. Many home routers that connect smart devices to the Internet are actually NAPT routers and often do not run a routing protocol.

NAT and NAPT greatly alleviate IPv4 address shortages but are not completely transparent to applications. Communication generally has to originate inside the private network, so an internal private-address host cannot directly act as an Internet server. Applications such as P2P that need externally initiated communication may require special NAT-traversal techniques.

6 IP Multicast

Multicast provides one-to-many communication. Compared with traditional one-to-one unicast, it can greatly save network resources, especially when a multicast group has many members. Multicast over the Internet is called IP multicast.

6.1 IP Multicast Addresses and Multicast Groups

IPv4 uses Class D addresses as multicast addresses. They can be destination addresses but not source addresses. Each Class D address identifies a multicast group; all hosts receiving datagrams through the same IP multicast address constitute that group.

Group membership can change at any time: a host may join or leave freely. Neither the number nor the geographical distribution of members is restricted, and a host may belong to several groups. A nonmember can also send datagrams to a group. Delivery is best effort and is not guaranteed to reach every member.

IPv4 multicast addresses are further divided into reserved or permanent multicast addresses, globally available multicast addresses, and administratively scoped multicast addresses, as described in RFC 3330.

IP multicast includes hardware multicast confined to a local area network and multicast across the Internet. Because most hosts access the Internet through LANs, the final stage of Internet multicast still uses LAN hardware multicast to deliver datagrams to all local group members.

6.2 Hardware Multicast on a LAN

An IPv4 multicast address can be mapped to a multicast MAC address. The IP multicast datagram is then encapsulated in a MAC frame whose destination address is the mapped multicast MAC address. This makes it possible to implement local IP multicast through hardware multicast. When a host is configured with its group's IP multicast address, the system generates the corresponding LAN multicast MAC address according to the mapping rules.

IANA uses Ethernet multicast addresses from 01-00-5E-00-00-00 through 01-00-5E-7F-FF-FF, from its IEEE-registered address block, to map IPv4 multicast addresses. Their first 25 bits are fixed and the remaining 23 vary, giving 2232^{23}223 addresses.

The first 5 of the 28 variable bits in an IPv4 multicast address cannot be mapped into the MAC address. Consequently, the mapping is not one-to-one.

A receiving host must therefore also filter the datagram in network-layer software and discard multicast datagrams that it does not want to receive.

6.3 Protocols Related to IP Multicast

Internet multicast requires multicast routers to forward datagrams across multiple networks. A multicast router examines the destination multicast address and forwards the datagram toward LANs containing members of that group. Two kinds of protocols are involved:

  • Internet Group Management Protocol (IGMP): informs the multicast router on a local LAN whether a host, or more precisely a process on a host, has joined or left a group. IGMP operates only on the local network. It does not reveal the total number of members or the networks across which they are distributed.

  • Multicast routing protocols (MRPs): establish a multicast forwarding tree between routers for each group. The tree connects the source to all routers with group members. Datagrams are flooded along this tree, then delivered to local members through hardware multicast.

Different groups require different forwarding trees. These trees must adapt dynamically to membership changes even when the network topology has not changed, making multicast routing more complex than unicast routing such as RIP or OSPF. A host need not belong to a group to send multicast datagrams to it. A forwarding tree may also pass through routers without local group members, such as R2 below, to reach all members.

6.4 Internet Group Management Protocol (IGMP)

IGMP has three message types:

  • Membership report.

  • Membership query.

  • Leave group.

IGMP messages are encapsulated in IP datagrams.

The basic operation includes joining a group, monitoring membership changes, and leaving a group.

Joining a group: different MAC addresses.

Joining a group: identical MAC addresses.

Monitoring membership changes:

A network may contain several multicast routers, but they do not all need to send periodic membership queries. One is elected as the querier; the others passively receive the responses and update their group lists. A router withdraws from the election when it hears a query whose source IP address is smaller than its own. Ultimately, the multicast router with the smallest IP address becomes the querier.

IGMPv2 adds an option to IGMPv1: a host leaving a group may proactively send a leave-group message rather than wait for a query, allowing the router to detect departures sooner.

6.5 Multicast Routing Protocols (MRPs)

The main task of a multicast routing protocol is to establish a forwarding tree connecting the source and routers with members of a group. There are two approaches.

Source-based tree routing uses a separate tree rooted at the source. A typical algorithm is reverse path multicasting (RPM), which has two steps:

  • Use reverse path broadcasting (RPB) to build a broadcast forwarding tree. Reverse path means treating the source as the destination when calculating shortest paths.

  • Prune downstream routers without group members to obtain a multicast forwarding tree.

Flooding can be used to construct a broadcast forwarding tree.

The tree generated by RPB has no loops, preventing broadcast packets from circulating indefinitely. On receiving a broadcast packet, a router first checks whether it arrived along the shortest path from the source. If so, the router forwards it through all interfaces except the incoming interface; otherwise, it discards it. If several neighboring routers provide equally short paths to the source, only one is selected: the path through the neighbor with the smallest IP address.

Example.

Group-shared tree routing uses a core-based distributed spanning-tree algorithm. Each group designates a core router as the root of a shared tree connecting all its member routers. Other member routers unicast join messages toward the core. A join message is forwarded until it reaches a router already on the multicast tree or reaches the core itself. The path followed by the message defines a branch from the joining edge router toward the core, and this branch is grafted onto the existing tree.

6.6 Mobile IP

Mobile IP, developed by the IETF and described in RFC 3344, lets a mobile host retain its original IP address while roaming between networks. It also provides mechanisms allowing stationary hosts to send datagrams correctly to mobile hosts.

  • Home network: the network to which a mobile host connects by default or initially registers for access.

  • Home address or permanent address: the host's address on its home network, which remains unchanged throughout mobile communication.

  • Home agent: the entity on the home network that performs mobility-management functions for the mobile host. It is usually a router on that network, with its agent functions implemented at the network layer.

  • Foreign or visited network: the network in which the mobile host is currently roaming.

  • Foreign agent: the entity assisting the mobile host with mobility management on the foreign network, usually a router.

  • Care-of address: a temporary address belonging to the foreign network and supplied to the mobile host by the foreign agent.

Agent discovery and registration:

Mobile host A contacts the foreign agent through agent discovery, obtains a care-of address, and registers its home address and home-agent address with the foreign agent. The foreign agent records the permanent address and registers the care-of address with the home agent; the mobile host may also register directly.

The home agent records the care-of address, receives datagrams on behalf of the absent mobile host, and forwards them through an IP tunnel to the foreign network. While the mobile host is away, the home agent answers ARP requests for the host with its own MAC address, using proxy ARP. It also sends ARP broadcasts claiming the mobile host's address so that other hosts and routers quickly update their ARP caches and send the host's datagrams to the home agent.

Sending datagrams from a stationary host to a mobile host:

When the foreign agent and mobile host are different devices, the care-of address is the foreign agent's address. It is neither the source address of the mobile host's outgoing original datagrams nor the destination address of its incoming original datagrams; it is only the exit address of the home-agent-to-foreign-agent tunnel. Mobile hosts using the same foreign agent can share this care-of address.

After decapsulating a tunneled datagram, the foreign agent looks up the MAC address associated with the mobile host's permanent address in its registration table. It encapsulates the datagram in a frame addressed to that MAC address and delivers it to the host.

Sending datagrams from a mobile host to a stationary host:

Mobile host A sends the datagram normally. Since IP routing does not depend on its source address in this procedure, the datagram is routed directly to stationary host B without passing through the home agent. The mobile host may use the foreign agent as its default router or obtain another foreign-network router's address through agent discovery and use that router instead.

Co-located care-of address:

Triangular routing:

Even if a more efficient path exists between a stationary and mobile host, datagrams to the mobile host first go through the home agent. This makes forwarding inefficient. One solution equips the stationary host with a communication agent. That agent obtains the care-of address from the home agent and then tunnels datagrams directly to the foreign agent, bypassing the home agent. This increases complexity and requires changes at the stationary host, so it is no longer transparent to that host.

7 IPv6

The main changes introduced by IPv6 are:

  • A larger address space: IPv4's 32-bit addresses are extended to 128 bits, which should not be exhausted in the foreseeable future with reasonable addressing.

  • An expanded addressing hierarchy: more levels can reflect the Internet topology more accurately and provide greater flexibility in addressing and routing design.

  • A flexible header format: incompatible with the IPv4 header, with optional extension headers providing more functions and more efficient router processing. Routers do not process extension headers other than hop-by-hop options.

  • Improved options: packets may contain new kinds of optional control information rather than being restricted to IPv4's fixed options.

  • Continued protocol expansion: new functions can be added as technology and applications develop.

  • Plug-and-play support: hosts and routers can automatically configure IPv6 addresses and other parameters without requiring DHCP.

  • Resource preallocation: better quality-of-service support for real-time audio, video, and other applications requiring bandwidth and delay guarantees.

7.1 Datagram Header

Extension headers are not part of the IPv6 base header. Together with the following data, they constitute the payload.

Compared with the IPv4 header, the IPv6 base header removes unnecessary functions and has only eight fields. Nevertheless, because addresses grow to 128 bits, the base header is 40 bytes long, 20 bytes longer than IPv4's fixed header. The changes are:

  • Header length is removed because the base header is always 40 bytes.

  • Differentiated services, formerly type of service, is replaced by traffic class and flow label functions.

  • Total length is replaced by payload length because only the data after the fixed base header has variable length.

  • Identification, flags, and fragment offset move to a fragmentation extension header.

  • TTL is renamed hop limit to match its function.

  • Protocol is replaced by next header.

  • The header checksum is removed to accelerate router processing.

  • Options are implemented through extension headers.

The fields of the IPv6 base header are as follows.

Version: 4 bits, indicating the IP version; its value is 6 for IPv6.

Traffic class: 8 bits, distinguishing categories or priorities of IPv6 datagrams. Different traffic-class performance characteristics have been investigated experimentally.

Flow label: 20 bits. A flow is a sequence of IPv6 datagrams from a particular source to a particular unicast or multicast destination, such as real-time audio or video, for which routers along the path provide the indicated quality of service. Datagrams belonging to one flow share a flow label, which is used for resource allocation. It is particularly useful for real-time traffic; traditional non-real-time traffic can use a value of 0.

Payload length: 16 bits, giving the number of bytes after the base header, including extension headers and data. Its maximum value is 65535, giving a maximum payload of 65535 bytes in this format.

Next header: 8 bits, corresponding to IPv4's protocol or options information. Without extension headers, it identifies the PDU immediately after the base header, such as 6 for TCP or 17 for UDP. With extension headers, it identifies the first extension header.

Hop limit: 8 bits, preventing indefinite circulation. The source sets a limit of at most 255 hops. Each forwarding router subtracts 1 and discards the datagram when the value reaches 0. Its operation is the same as IPv4's TTL, but its name more directly reflects its purpose.

Source address and destination address: 128 bits each, identifying the datagram's sender and receiver.

7.2 Extension Headers

IPv6 moves IPv4-style options to extension headers, normally processed by the source and destination rather than intermediate routers, except for hop-by-hop options. RFC 2460 defines six extension-header types:

  • Hop-by-hop options.

  • Routing.

  • Fragment.

  • Authentication.

  • Encapsulating security payload.

  • Destination options.

Each consists of several fields and may have a different length. Its first field is an 8-bit next-header field identifying the following extension header. When several extension headers are used, they appear in the order above.

7.3 IPv6 Addresses

IPv6 uses colon-separated hexadecimal notation. Leading-zero omission and consecutive-zero compression make addresses more concise. Leading-zero omission removes an initial run of zeros within a hexadecimal group. Consecutive-zero compression replaces consecutive zero groups with a double colon.

Example.

Zero compression may be used only once in an address; otherwise the representation would be ambiguous. Colon-hexadecimal notation can also use a dotted-decimal suffix, which is useful during the transition from IPv4.

CIDR slash notation is also used in IPv6.

There are three basic destination-address types:

  • Unicast: traditional point-to-point communication.

  • Multicast: one-to-many communication, delivering a datagram to every computer in a group. IPv6 treats broadcast as a special case of multicast rather than introducing a separate broadcast type.

  • Anycast: delivers a datagram to one member of a group, usually the closest member according to the routing algorithm.

RFC 4291 classifies IPv6 addresses as follows:

  • Unspecified address: all 128 bits are zero, abbreviated as ::. It cannot be a destination address and is used as a source by a host without a configured standard IPv6 address. There is only one such address.

  • Loopback address: the lowest bit is 1 and the other 127 bits are zero, written as 0:0:0:0:0:0:0:1 or ::1. It serves the same purpose as IPv4 loopback and is unique.

  • Multicast addresses: the highest 8 bits are all ones, written as FF00::/8. They serve the same role as IPv4 multicast addresses and occupy 1/2561/2561/256 of the IPv6 address space.

  • Link-local unicast addresses: the highest 10 bits are 1111111010, written as FE80::/10. Hosts can use them to communicate on a local network even without Internet access, but not to communicate with Internet hosts. They occupy 1/10241/10241/1024 of the address space.

  • Global unicast addresses: the most widely used category. They use a three-level structure to accelerate routing lookups.

7.4 Transition from IPv4 to IPv6

The enormous number of IPv4 routers prevents an instantaneous transition. Migration must be gradual, and newly deployed systems need mechanisms to receive, forward, and route IPv4 datagrams as well. Two transition strategies are introduced here.

Dual stack installs both IPv4 and IPv6 protocol stacks on some hosts or routers before the transition is complete. An IPv6/IPv4 host or router has both kinds of address and can communicate with either system. A dual-stack source queries DNS for the destination address and uses IPv4 or IPv6 according to the returned address type.

Tunneling encapsulates an entire IPv6 datagram as the payload of an IPv4 datagram when entering an IPv4 network. The outer datagram crosses that network. On leaving it, the IPv6 datagram is extracted and forwarded into an IPv6 network.

7.5 Internet Control Message Protocol Version 6 (ICMPv6)

Like IPv4, IPv6 does not guarantee reliable delivery and needs control messages to report errors to the source. ICMPv6 is more complex than ICMPv4 because it incorporates the functions previously provided by ARP and IGMP, bringing these companion network-layer functions into one protocol. ICMPv6 messages are encapsulated in IPv6 datagrams.

ICMPv6 messages report errors, obtain information, discover neighbors, and manage multicast communication. Different RFCs classify the messages differently: RFC 2463 defines six types, RFC 2461 defines five types, and RFC 2710 defines three types.

8 Software-Defined Networking

Software-defined networking (SDN) separates the forwarding plane from the control plane. The concept was proposed by Stanford professor Nick McKeown in 2009 and initially discussed as a new academic network architecture.

He also taught Stanford CS144; publicly available videos of that year's course can be found on Bilibili.

An SDN controller provides centralized control and a global view. It dynamically computes suitable paths according to applications' network requirements and installs flow tables in switches, enabling efficient, on-demand data transmission.

  • Northbound interfaces provide access and network-management interfaces upward to vendors or operators.

  • Southbound interfaces manage other vendors' network-management systems or devices below the controller.

  • East–west interfaces connect SDN servers.

Reasons for introducing SDN include the following problems with traditional networks:

  • Devices pass information to their next-hop neighbors to remove failed links, but this lacks global control and may produce redundant information.

  • The continuous development of IoT causes traffic to grow almost exponentially, increasing device numbers, pressure on infrastructure, and routing convergence time while reducing efficiency.

  • Traditional networks are not programmable, making efficient, on-demand transmission difficult.

  • Hardware, operating systems, and applications are tightly coupled in closed, incompatible systems that are difficult to configure and manage.

SDN combines general-purpose underlying hardware, software-defined functions, and an open-source model. It provides consistent upgrade and management commands and unified configuration methods. Further abstraction of the control plane makes configuration more flexible and moves network management from managing complexity toward extracting simplicity, with greater automation and intelligence. Separating control from data forwarding makes the network programmable.

SDN may be understood at three scopes:

  • Narrow: equivalent to OpenFlow.

  • Broad: separation of control and forwarding.

  • Very broad: separation of management and control. Software scripts send commands to remote switches, but the switches still run traditional Layer 2 and Layer 3 protocols, so control and forwarding remain together.

SDN generally has three layers. The infrastructure layer contains routers, switches, and similar devices.

Google B4 is a practical example. Data centers are particularly well suited to SDN.
