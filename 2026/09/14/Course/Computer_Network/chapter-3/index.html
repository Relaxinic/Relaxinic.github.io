Link: A physical line (wired or wireless) from one node to an adjacent node, with no other switching nodes in between.

Data link: When transmitting data over a link, in addition to the link itself, certain necessary communication protocols are required to control the transmission of this data. Adding the hardware and software that implement these protocols to the link constitutes a data link.

  • The network adapter in a computer (commonly known as a network card) and its corresponding software driver implement these protocols; a typical network adapter includes the functions of both the physical layer and the data link layer.

Frame: The PDU for horizontal logical communication between peer entities at the data link layer.

Services provided by the data link layer

  • Unacknowledged connectionless service: The receiver does not acknowledge the received frames. Applicable scenarios: reliable channels with low bit error rates, real-time communication. Network example: Ethernet.

  • Acknowledged connectionless service: Each frame receives an individual acknowledgment. Applicable scenarios: unreliable channels (wireless channels). Network example: 802.11.

  • Acknowledged connection-oriented service. Applicable scenarios: unreliable channels with long delays.

SDLC / HDLC: Synchronous / High-level Data Link Control

Piggybacking: When the receiver has data to send to the sender, it does not immediately send a pure acknowledgment frame. Instead, it temporarily delays sending the ACK, waiting until the next service data frame is ready to be sent, and then "attaches" the acknowledgment information to the header or a specific field of this data frame and sends it along with it.

1 Three questions

1.1 Encapsulation into frames and transparent transmission

Encapsulation into frames: The data link layer adds the beginning and end of the frame to the PDU delivered by the upper layer to make it a frame.

  • The beginning and end of the frame contain some important control information.

  • Another function of the beginning of the frame and the end of the frame is frame delimitation, but not every frame of the data link layer protocol contains the frame delimitation mark (such as the MAC frame of Ethernet V2)

  • In order to improve the efficiency of transmission frames, the length of the data load of the frame should be as greater than the length of the first and tail as possible.

  • Considering many factors such as the demand for cache space and error control, each data link layer protocol stipulates the maximum length of the frame's data load, that is, the maximum transfer unit (MTU)

Transparent transmission: make the data link layer have no restrictions on the content of the PDU delivered by the upper layer, as if the data link layer does not exist.

  • Byte-oriented physical links use the method of byte filling to achieve transparent transmission.

  • Bit-oriented physical links use the method of bit filling to achieve transparent transmission.

1.2 Error detection

Frames may have errors during the transmission process.

Bit errors may occur during transmission (called bit errors). Bit 1 may become bit 0, and vice versa.

Over a period of time, the ratio of the number of bits transmitted to the total number of bits transmitted is called the bit error rate (BER)

Increasing the signal-to-noise ratio of the link can reduce the error rate; but in the actual communication link, it is impossible to reduce the error rate to zero.

The receiving party can detect whether there is an error code in the frame according to the error code added by the sender at the end of the frame. The commonly used verification methods are:

Odd-even check

  • Odd check is to add a check bit after the data to be sent, so that the number of bits 1 in the entire data after adding the check bit is odd.

  • Even check is to add a check bit after the data to be sent, so that the number of bits 1 in the whole data after adding the check bit is even.

  • In the transmitted data, if there is an error in the odd bit, the oddity of the number of bits contained in bit 1 will change, and the error code can be detected.

  • In the transmitted data, if there is an error code in an even number of bits, the parity of the number of bits contained in 1 will not change, and the error code cannot be detected (missed detection)

  • In actual use, the parity check can be divided into vertical parity check, horizontal paparity check and horizontal vertical papamity check.

Cyclic redundancy check(cyclic redundancy check, CRC)

This technology with extremely low leakage rate is widely used in the data link layer, because although the calculation is relatively complex, it is very easy to implement with hardware.

The sending and receiving parties agreed to generate a polynomial G(X)G(X)G(X). Based on the data to be sent and G(X)G(X)G(X), the sender calculates the error detection code (redundant code, the length is the maximum number of polynomials generated), and adds the redundant code to the back of the data to be sent and transmits it together.

Redundant code calculation steps:

  1. Construct the divisor: add the maximum number of polynomials to be generated after the data to be sent 0

Two. Construct divisors: generate a bit string composed of coefficients of polynomials as divisors

  1. Do binary module 2 division: equivalent to the logical difference or operation of the corresponding bit

  2. Check the remainder: The number of digits of the remainder should be the same as the maximum number of times to generate a polynomial. If the number of digits is insufficient, add 0 before the remainder to make up the number of digits.

After the recipient receives the data and redundant code, it calculates whether the received data and redundant code have errors through G(X)G(X)G(X)

Specific steps:

  1. Construct the divisor: the received information is used as the divisor

Two. Construct divisors: generate a bit string composed of coefficients of polynomials as divisors

  1. Do binary module 2 division: equivalent to the logical difference or operation of the corresponding bit

  2. Check the remainder: If the remainder is 0, it can be considered that there is no error code in the transmission process; if the remainder is not 0, it can be considered that there is an error code in the transmission process.

Error detection techniques such as parity checks and cyclic redundancy checks can only detect that an error occurred during transmission, but cannot locate the error, and therefore cannot correct it. To correct errors in transmission, error-correcting codes with more redundant information (such as Hamming codes) can be used for forward error correction. However, error-correcting codes have relatively high overhead and are rarely used in computer networks.

In computer networks, the error detection and retransmission methods introduced later are usually used to correct errors in transmission, or frames in which errors are detected are simply discarded, depending on whether the data link layer provides reliable transmission service or unreliable transmission service to its upper layer.

1.3 Reliable Transmission

Unreliable transmission service: simply discards frames with bit errors and does nothing else.

Reliable transmission service: ensures that whatever the sender sends can ultimately be correctly received by the receiver.

In general, the bit error rate of wired links is relatively low. Therefore, to reduce overhead, the data link layer is not required to provide reliable transmission service to its upper layers; even if bit errors occur, the problem of reliable transmission is handled by its upper layers.

Wireless links are susceptible to interference and have a relatively high bit error rate. Therefore, the data link layer is required to provide reliable transmission service to its upper layers.

Transmission errors (the first three situations occur in the upper layers of the data link layer, and the last one occurs in the data link layer and its lower layers):

  • Bit errors (bit errors): just introduced above.

  • Packet loss: when the input queue is almost full, received packets are actively discarded.

  • Packet out-of-order: the order in which packets arrive differs from the order in which they were sent.

  • Packet duplication: when a router is busy, packets wait for a long time in the input queue, causing the sender to time out and retransmit, so that the receiver ultimately receives multiple identical packets.

Reliable transmission service is not limited to the data link layer; all other layers may also choose to implement reliable transmission.

The implementation of reliable transmission is relatively complex and has relatively high overhead. Whether to use reliable transmission depends on application requirements.

Stop-and-wait protocol:

If the receiver does not receive the data packet, it will not send the corresponding ACK or NAK. If no measures are taken, the sender will remain in the state of waiting for the receiver's ACK or NAK.

To solve the above problem, the sender can start a timeout timer each time it finishes sending a data packet.

If the retransmission time-out (RTO) set by the timeout timer is reached but the sender still has not received the receiver's ACK or NAK, it retransmits the data packet that was previously sent. Generally, the RTO can be set slightly larger than the average round-trip time RTT between the sender and receiver.

To avoid the transmission error of duplicate packets, each packet must carry a sequence number. For the stop-and-wait protocol, since the sender stops and waits after sending each data packet, it is enough to ensure that each time a new data packet is sent, its sequence number is different from that of the previously sent data packet. Therefore, one bit is enough for numbering (0/1).

If the receiver receives a duplicate data packet, it discards it and sends another acknowledgment packet. The acknowledgment packet also needs to be numbered to prevent the sender from mistaking which data packet the acknowledgment packet corresponds to. The number of bits used is the same as the number of bits used for the data packet.

After using the timeout retransmission mechanism, the negative acknowledgment mechanism can be omitted, which makes the protocol simpler to implement. However, if the bit error rate of the point-to-point link is relatively high, using the negative acknowledgment mechanism can enable the sender to retransmit as soon as possible before the timeout timer expires.

The stop-and-wait protocol belongs to the automatic repeat request (ARQ) protocol, that is, the retransmission request is automatically made by the sender, rather than the receiver requesting the sender to retransmit a certain erroneous data packet.

Channel utilization:

  • If timeout retransmission occurs, the channel utilization rate will be even lower for transmitting useful data information.

  • When the RTT is relatively large, in order to improve channel utilization, the sender and receiver are not suitable for using the stop-and-wait protocol, and instead can choose to use the Go-Back-N (GBN) protocol or the Selective Repeat (SR) protocol.

Go-Back-N Protocol (GBN)

Using pipelined transmission can significantly improve channel utilization.

At this time, the sender cannot continuously send data packets without limit; otherwise, routers in the network or the receiver may not have enough time to process these data packets, which may lead to the loss of data packets. This is actually a waste of network resources.

Therefore, in addition to using pipelined transmission, the Go-Back-N protocol also uses a sending window to limit the number of data packets the sender can continuously send. This belongs to the continuous ARQ protocol.

  • nnn bits are used to number the packets, and the sequence number range is 0∼(2n−1)0 \sim (2^n - 1)0∼(2n−1) (in this example, it is assumed that 3 bits are used to number the packets).

Each time the receiver correctly receives a data packet whose sequence number falls within the receiving window, it slides the receiving window forward by one position, so that a new sequence number falls within the receiving window; at the same time, the receiver also needs to send an acknowledgment packet for that data packet to the sender.

Each time the sender receives an acknowledgment packet that is acknowledged in order, it slides the sending window forward by one position, so that a new sequence number falls within the sending window, and data packets whose sequence numbers fall within the sending window can continue to be sent.

During the operation of the Go-Back-N protocol, the sender's sending window and the receiver's receiving window continuously slide forward according to the above rules (because this type of protocol is also called a sliding window protocol).

The receiver uses cumulative acknowledgment: the receiver does not have to send an acknowledgment packet for every data packet it receives; instead, after receiving several data packets with consecutive sequence numbers, it can send an acknowledgment packet for the last data packet that arrived in order. The Point-to-Point Protocol (PPP) is currently the most widely used point-to-point data link layer protocol.

Two applications:

2.1 Frame Format

Flag field: The delimiter of a PPP frame, with a value of 0x7E

Address field: The value is 0xFF, reserved

Control field: The value is 0x03, reserved

To improve efficiency, this field may be omitted during frame transmission

Protocol field: Its value is used to indicate to which protocol the frame's data payload should be delivered for processing

Frame check sequence (FCS) field: Its value is the error-detection code calculated using CRC

Possible PDUs are: IP datagram / LCP packet / NCP packet

2.2 Transparent Transmission

Byte-oriented asynchronous links use byte stuffing to achieve transparent transmission. Specifically, the data payload of a frame contains several flag fields whose value is equal to the delimiter value of a PPP frame, which is 0x7E.

Processing at the sender:

  • For each 0x7E that appears in the data payload, subtract 0x20 (equivalent to XORing with 0x20), and then insert the escape character 0x7D before it.

  • If the data payload originally contains 0x7D, subtract 0x20 from each 0x7D, and then insert the escape character 0x7D before it.

  • For each ASCII control character that appears in the data payload (that is, a character whose value is less than 0x20), add 0x20 (equivalent to XORing with 0x20, converting it into a non-control character), and then insert the escape character 0x7D before it.

Processing at the receiver: perform the reverse transformation of the sender, and the original data payload that has not undergone byte stuffing can be correctly recovered.

Bit-oriented synchronous links use zero-bit stuffing to achieve transparent transmission.

Processing at the sender: scan the data payload of the frame (generally done by hardware), and whenever 5 consecutive 1 bits appear, stuff one 0 bit after them.

Processing at the receiver: scan the data payload of the frame, and whenever 5 consecutive 1 bits appear, delete the one 0 bit after them.

2.3 Error Detection

Error detection is implemented using the FCS field in the frame.

The generator polynomial of the CRC algorithm used in this field is: CRC-CCITT=x16+x12+x5+1\text{CRC-CCITT} = x^{16} + x^{12} + x^5 + 1CRC-CCITT=x16+x12+x5+1

Whenever the receiver receives a PPP frame, it performs a CRC check; if the CRC check is correct, it accepts the frame; otherwise, it discards the frame.

Therefore, the data link layer using PPP provides an unreliable data transmission service to the layer above.

3 Shared Ethernet

Ethernet is named after "Ether," the hypothetical medium for electromagnetic wave propagation.

3.1 Network Adapters and MAC Addresses

To connect a computer to Ethernet, a corresponding network adapter is required, commonly referred to simply as a "network card." The structure of a network card is as follows:

Inside the computer, communication between the network card and the CPU is generally carried out in parallel transmission via the I/O bus on the computer motherboard.

Communication between the network card and the external Ethernet (local area network) is generally carried out in serial mode via transmission media (coaxial cable, twisted-pair cable, optical fiber).

In addition to implementing physical layer and data link layer functions, another important function of the network card is to convert between parallel transmission and serial transmission.

Since the transmission rate of the network and the transmission rate on the computer's internal bus are not the same, the core chip of every network card includes memory for buffering data.

Assuming the network card hardware is correct, for the network card to work properly, a corresponding device driver must be installed for it in the computer's operating system; the driver is responsible for driving the network card to send and receive frames.

In point-to-point channels, the data link layer does not need addresses; however, in broadcast channels, the data link layer must use addresses as unique identifiers to distinguish hosts. The header of each frame sent by a host carries the data link layer addresses of the sending host (source host) and the receiving host (destination host). Since such addresses are used for medium access control (MAC), they are called MAC addresses.

MAC addresses are generally burned into the electrically erasable programmable read-only memory (EEPROM) of the network card, so MAC addresses are also called hardware addresses or physical addresses (having nothing to do with the "physical" in "physical layer").

Generally, an ordinary user's computer often contains two network cards: one is an Ethernet card for connecting to a wired local area network, and the other is a Wi-Fi card for connecting to a wireless local area network. Each network card has a globally unique MAC address. Switches and routers often have more network interfaces, so they possess more MAC addresses. Therefore, strictly speaking, a MAC address is a unique identifier for each interface on the network, not for each device on the network.

MAC address transmission order:

  • Byte transmission order: 1st byte -> 6th byte

  • Bit transmission order: b0 -> b7

Each time the network card receives a frame from the network, it checks the destination MAC address in the frame header and handles it as follows:

  1. If the destination MAC address is the broadcast address (FF-FF-FF-FF-FF-FF), the frame is accepted.

  2. If the destination MAC address is the same as the globally unique unicast MAC address burned into the network card, the frame is accepted.

  3. If the destination MAC address is a multicast address supported by the network card, the frame is accepted.

  4. If none of the above three cases apply, the frame is discarded.

A network card can also be set to a special working mode: promiscuous mode. A network card working in promiscuous mode will accept any frame received from the shared medium, regardless of what the frame's destination MAC address is.

For network maintenance and management personnel, this mode allows monitoring and analysis of traffic on the local area network in order to identify specific measures to improve network performance.

A sniffer is a type of network card working in promiscuous mode; combined with corresponding tool software (WireShark), it can serve as a very useful network tool for learning about and analyzing networks.

Promiscuous mode is like a "double-edged sword"; hackers often use this mode to illegally obtain network users' passwords.

A globally unique unicast MAC address is like the ID number on an ID card—it is unique and is often bound to the user's personal information. Therefore, users should try their best to ensure that the globally unique unicast MAC addresses they own are not leaked.

To avoid the security problem of MAC address leakage when user devices connect to Wi-Fi hotspots, most mobile devices currently already employ random MAC address technology.

3.2 CSMA/CD Protocol

To solve the problem of stations contending for the bus, shared bus Ethernet uses a dedicated protocol called CSMA/CD (carrier sense multiple access / collision detection). The basic principles of this protocol are:

Multiple access (MA): Multiple stations are connected to a single bus and compete to use the bus.

Carrier sense (CS): Before sending a frame, each station must first check whether any other station is sending a frame on the bus ("listen before talking").

  • If the bus is detected as idle for 96 bit times (the time required to transmit 96 bits, also called the minimum interframe gap), then the frame is sent.

  • If the bus is detected as busy, the station continues to monitor and waits until the bus becomes idle for 96 bit times, then sends the frame.

Collision detection (CD): Each station that is sending a frame detects collisions while sending ("listen while talking").

  • Once a collision is detected on the bus, the station immediately stops sending, backs off for a random period of time, and then starts again from carrier sense before sending.

Collision reinforcement: Once a station sending a frame detects a collision, in addition to immediately stopping transmission of the frame, it also continues to send a 32-bit or 48-bit artificial jamming signal so that there are enough collision signals for all stations to detect the collision.

On a shared-bus Ethernet using the CSMA/CD protocol, each station only tries to avoid collisions and, when a collision occurs, performs backoff and retransmits; collisions cannot be completely avoided.

When using the CSMA/CD protocol, because a station that is sending a frame must "detect collisions while sending the frame," a station cannot send and receive at the same time. That is, full-duplex communication is impossible; only half-duplex communication (two-way alternating communication) is possible.

Any station on a shared-bus Ethernet using the CSMA/CD protocol may encounter a collision while sending a frame. Then, from the moment a station starts sending a frame, what is the longest time it may take to detect that its frame has collided with a frame sent by another station? This is analyzed in detail below.

In summary, from the moment a station starts sending a frame, it takes at most a duration of 2τ2 \tau2τ (i.e., δ→0\delta \rightarrow 0δ→0) to detect whether the frame it sent has encountered a collision; this end-to-end round-trip time is called the contention period or collision window. If a station has not detected a collision after the contention period from the start of sending a frame, it can be certain that this transmission will not produce a collision.

From the concept of the contention period, it can be seen that every station on a shared-bus Ethernet may encounter a collision from the moment it starts sending a frame until a short time afterward, and the length of this short time is uncertain. It depends on the distance between the station sending the other frame and this station, but it will not exceed the end-to-end round-trip propagation delay of the bus, that is, one contention period. Obviously, the longer the bus (the greater the one-way end-to-end propagation delay) and the more stations in the network, the greater the probability of collision. Therefore, the bus length of a shared Ethernet cannot be too long, and the number of connected stations cannot be too large.

A 10 Mb/s shared-bus Ethernet (traditional Ethernet) specifies that the contention period is the transmission time of 512 bits, i.e., 51.2 μs.

In addition to the signal propagation delay, consideration is also given to the delay caused by repeaters that may exist in the network and the duration for which a 32-bit or 48-bit artificial jamming signal continues to be sent when a collision occurs.

A shared-bus Ethernet specifies that the bus length cannot exceed 2500 m.

To ensure that every station on a shared-bus Ethernet can detect whether a collision has occurred before it finishes sending a complete frame, the frame transmission delay cannot be less than one contention period. For a 10 Mb/s shared-bus Ethernet, the minimum frame length is 512 b, i.e., 64 B.

When a station is sending a frame, if the first 64 B of the frame do not encounter a collision, then the subsequent part of the frame will not encounter a collision either; that is, if a collision occurs, it must occur within the first 64 B of the frame.

Because a station sending a frame detects collisions while sending the frame, once a collision is detected it immediately aborts transmission of the frame. At this time, the amount of data already sent must be less than 64 B; therefore, when a receiving station receives a frame whose length is less than 64 B, it can determine that this is an invalid frame that was abnormally aborted due to a collision and can simply discard it.

Generally speaking, the length of the frame's data payload should be much greater than the total length of the frame header and trailer, so that the frame transmission efficiency can be improved. However, if the upper limit of the data payload length is not restricted, the frame length may become too long, which brings some problems.

In a shared bus Ethernet using the CSMA/CD protocol, a station that is sending a frame detects collisions while sending the frame. When a collision is detected, it immediately stops sending, backs off for a random period of time, and then resends. Each station uses the truncated binary exponential backoff algorithm to select the random backoff time.

If collisions occur repeatedly over multiple consecutive transmissions, it indicates that there may be more stations competing for the channel. However, using the above backoff algorithm can make the average delay required for retransmission increase with the number of retransmissions (i.e., dynamic backoff), thereby reducing the probability of collisions.

When retransmission still fails after 16 attempts, it indicates that there are too many stations intending to send frames at the same time, resulting in continuous collisions. At this point, retransmission should be abandoned and reported to the higher layer.

Consider the following ideal situation:

As soon as the bus becomes idle, a station immediately sends a frame.

No collisions occur when stations send frames.

The time a frame occupies the bus is T0+τT_0 + \tauT0​+τ, while the transmission time of the frame itself is T0T_0T0​.

3.3 Shared Ethernet Using Hubs

In the early days, Ethernet used a device called a hub that replaced the bus with a large-scale integrated circuit and was very reliable; the transmission medium connected to the hub also turned to cheaper and more flexible twisted pair cables.

Characteristics of the huser:

  • Although the physical topology of Ethernet using the hub is star, it is still a bus network logically; each station on the bus shares bus resources and still uses the CSMA/CD protocol.

  • The hub only works at the physical layer, and each interface of it simply forwards bits without collision detection; the task of collision detection is the responsibility of the network card in each site.

  • The hub generally has a small amount of fault tolerance and network management functions; for example, if the network card of a site in the network fails and keeps sending frames, the hub can detect this problem and disconnect the connection with the faulty network card internally, so that the entire Ethernet can work normally.

IEEE formulated the 10BASE-T star Ethernet standard 802.3i in 1990, which is a very important milestone in the history of LAN development, laying a solid foundation for Ethernet's dominance in LAN.

The communication distance of 10BASE-T Ethernet is relatively short, and the distance from each station to the hub cannot exceed 100m.

IEEE 802.3 Ethernet can also use optical fiber as a transmission medium. The corresponding standard is 10BASE-F, where "F" means optical fiber, which is mainly used for remote connection between hubs.

3.4 Extending Ethernet at the Physical Layer

In a shared bus Ethernet, the distance between two stations cannot be too far; otherwise, the signals transmitted between them will attenuate to the point where the CSMA/CD protocol cannot work properly.

In the early days when thick coaxial cable or thin coaxial cable was widely used for shared bus Ethernet, in order to improve the network's geographic coverage, repeaters operating at the physical layer were commonly used. The IEEE 802.3 standard stipulates that two network segments can be connected by one repeater, and any two stations can pass through at most three network segments.

As 10BASE-T star Ethernet using twisted pair and hubs became the mainstream type of Ethernet, repeaters were rarely used to extend network coverage.

In 10BASE-T star Ethernet, the distance from each station to the hub cannot exceed 100 m, so the maximum communication distance between two stations cannot exceed 200 m. Optical fiber and a pair of fiber modems are generally used to extend the distance between a station and the hub.

This extension method is relatively simple, but the price to pay is: adding one fiber modem for converting electrical signals and optical signals to each station and each hub, as well as a pair of communication optical fibers between them.

Because signal attenuation and distortion in optical fiber are very small, this method can very simply extend the distance between a station and the hub to more than 1000 m.

An Ethernet hub generally has 8 to 32 interfaces. If the number of stations to be connected exceeds the number of interfaces that a single hub can provide, multiple hubs need to be used, so that a multilevel star Ethernet covering a larger area and connecting more stations can be formed. A multilevel star Ethernet formed by connecting multiple hubs expands network coverage and the number of stations, but also brings some negative factors.

A shared Ethernet extended at the physical layer is still one collision domain and cannot connect too many stations; otherwise, a large number of collisions may occur, resulting in average throughput that is too low.

3.5 Extending Ethernet at the Data Link Layer

A bridge operates at the data link layer (including the physical layer beneath it), so a bridge has the relevant capabilities that fall within the scope of the data link layer.

  • It can identify the structure of frames.

  • It can forward or discard received frames based on the destination MAC address in the frame header and the bridge's own frame forwarding table.

When forwarding frames to the network segments to which it is connected, a bridge's interfaces execute the corresponding medium access control protocol; for shared Ethernet, this is the CSMA/CD protocol.

A transparent bridge establishes a forwarding table through a self-learning algorithm.

  • "Transparent" in a transparent bridge means that each station in the Ethernet does not know which bridges will forward the frames it sends before they finally reach the destination station; that is, to each station, the bridges in the Ethernet are invisible.

  • The standard for transparent bridges is IEEE 802.1D.

The specific process is:

  1. After receiving a frame, the bridge registers it (i.e., self-learning). The registered content is the source MAC address of the frame and the port number through which it entered the bridge.

  2. The bridge forwards the frame according to the destination MAC address of the frame and the bridge's forwarding table, including the following three cases:

    • Explicit forwarding: the bridge knows from which port the frame should be forwarded.

    • Blind forwarding: the bridge does not know from which port the frame should be forwarded, so it can only forward it through all ports other than the port through which it entered the bridge.

    • Discarding: the bridge knows that the frame should not be forwarded and discards it.

If a bridge receives a frame with bit errors, it simply discards it.

If a bridge receives a broadcast frame with no bit errors, it does not need to look up the forwarding table; instead, it forwards the broadcast frame directly from all interfaces other than the one on which the broadcast frame was received.

Each record in the forwarding table has a valid lifetime and is automatically deleted upon expiration. This is because the correspondence between the MAC address of each station and the bridge interface is not permanent; for example, if a station replaces its network interface card, its MAC address will change.

To improve the reliability of Ethernet, it is sometimes necessary to use multiple transparent bridges between two Ethernets to provide redundant links. However, while adding redundant links improves Ethernet reliability, it also introduces loops into the network: broadcast frames in the network will circulate forever in the loop, causing broadcast frames to flood the entire network, wasting network resources, and preventing hosts in the network from communicating normally.

To avoid this problem, transparent bridges use the spanning tree protocol (STP), which can improve network reliability by adding redundant links while avoiding the problems caused by loops.

No matter how complex a looped topology the bridges are connected into, the bridges interact through bridge protocol data units (BPDUs) to find a connected subset of the original network topology (that is, a spanning tree) in which there are no loops in the entire connected network.

When bridges are connected for the first time or when the network topology changes (due to manual changes or failures), the bridges reconstruct the spanning tree to ensure network connectivity.

4 Switched Ethernet

Bridges have very few interfaces, usually only 2 to 4, and are generally used only to connect different network segments. The switching hub that appeared in 1990 is essentially a bridge with multiple interfaces, commonly called an Ethernet switch or a Layer 2 switch.

  • "Layer 2" means that the Ethernet switch operates at the data link layer (including the physical layer).

  • Like a bridge, the forwarding table inside a switch is also gradually and automatically established through a self-learning algorithm based on communication among hosts in the network.

  • In addition, switches also use STP to generate communication paths that can connect the entire network without creating loops.

An Ethernet that uses only switches (and no hubs) is a switched Ethernet.

Each port on a switch can connect to a computer, or to a hub or another switch.

When a switch port is connected to a computer or a switch, it can operate in full-duplex mode and can simultaneously connect multiple pairs of ports internally, so that each pair of communicating computers can transmit data without collisions, just as if each had exclusive use of the transmission medium; thus there is no need to use the CSMA/CD protocol.

When a switch port is connected to a hub, that port can only use the CSMA/CD protocol and can only operate in half-duplex mode.

Switches and network interface cards in computers today can automatically recognize the above two situations and automatically switch to the corresponding operating mode.

Switches generally have interfaces of multiple rates, such as 10 Mb/s, 100 Mb/s, 1 Gb/s, and even 10 Gb/s interfaces, and most interfaces support multi-rate auto-negotiation.

Ordinary switches generally use the "store-and-forward" method.

To reduce the forwarding delay of switches, some switches use cut-through switching. This type of switch immediately determines the forwarding interface for a frame based on the frame's destination MAC address while receiving the frame, and then forwards it through its internal hardware-based crossbar matrix, without having to buffer the entire frame before processing it. Therefore, the delay of cut-through switching is very small. However, because frames are forwarded directly without error checking, some invalid frames may be forwarded to other hosts.

4.1 Shared Ethernet vs. Switched Ethernet

In summary, the network performance of switched Ethernet is far higher than that of shared Ethernet, and hubs have long been replaced by switches.

Routers isolate both broadcast domains and collision domains.

  • Destination address / Source address: Used to fill in the destination MAC address and source MAC address of the frame.

  • Type: Its value is used to indicate which protocol of the upper layer encapsulates the content in the data payload, so that the data payload of the received MAC frame can be handed over to this protocol of the upper layer.

6 Virtual Local Area Network

A virtual local area network (VLAN) is a technology that divides stations within a local area network into logical groups unrelated to physical location. One logical group is one VLAN, and the stations in a VLAN have certain common application requirements.

Stations belonging to the same VLAN can communicate directly with each other, while stations in different VLANs cannot communicate directly.

A network administrator can configure each switch in the local area network to establish multiple logically independent VLANs.

Multiple stations connected to the same switch can belong to different VLANs, and multiple stations belonging to the same VLAN can be connected to different switches.

A VLAN is not a new type of network; it is merely a service that a local area network can provide to users.

VLAN implementation mechanism: The most common approach is to implement VLANs based on Ethernet switch interfaces, which requires Ethernet switches to implement the following two functions:

6.1 IEEE 802.1Q frames

The ability to process frames carrying VLAN tags, that is, IEEE 802.1Q frames.

  • It extends the Ethernet V2 MAC frame format: a 4-byte VLAN tag field is inserted between the source address field and the type field.

  • Tag Protocol Identifier (TPID): 16 bits long, with a fixed value of 0x8100, indicating that the frame is an IEEE 802.1Q frame.

  • Priority (PRI): 3 bits long, with a value range of 0 to 7; the larger the value, the higher the priority. When the network is congested, devices preferentially send 802.1Q frames with higher priority.

  • Canonical Format Indicator (CFI): 1 bit long; a value of 0 indicates that the MAC address is encapsulated in canonical format, and a value of 1 indicates that the MAC address is encapsulated in non-canonical format; for Ethernet, the value of CFI is 0.

  • VLAN Identifier (VID): 12 bits long, with a value range of 0 to 4095, of which 0 and 4095 are reserved and not used.

    • The VID is the number of the VLAN to which the 802.1Q frame belongs, and devices use the VID to identify the VLAN to which the frame belongs.

    • Broadcast frames are forwarded only within the same VLAN, thus limiting the broadcast domain to a single VLAN.

6.2 Ethernet Switches

802.1Q frames are generally not handled by user hosts, but by Ethernet switches:

  • When a switch receives an ordinary Ethernet MAC frame, it inserts a 4-byte VLAN tag into it to make it an 802.1Q frame. This process is referred to as "tagging."

  • When a switch forwards an 802.1Q frame, it may remove its 4-byte VLAN tag to make it an ordinary Ethernet MAC frame. This process is referred to as "untagging." When a switch forwards an 802.1Q frame, it may also not perform "untagging." Whether "untagging" is performed depends on the interface type of the switch.

The interfaces of a switch can support different interface types, and interfaces of different interface types handle frames differently.

  • According to the different ways interfaces handle frames when receiving and sending frames, as well as the different objects to which the interfaces connect, the interface types of Ethernet switches are generally divided into two types: Access and Trunk.

  • After an Ethernet switch is powered on and started, if no VLAN-related settings have been previously made for its interfaces, the interface type of each interface defaults to Access, and the default VLAN ID of each interface is 1, that is, each interface belongs to VLAN1 by default.

    • For Cisco switches, the default VLAN ID of an interface is called the native VLAN.

    • For Huawei switches, the default VLAN ID of an interface is called the port VLAN ID, abbreviated as PVID; each interface of the switch has one and only one PVID.

  • Access interface: generally used to connect to user computers.

    • Since it can belong to only one VLAN, its PVID value is the same as the ID of the VLAN to which it belongs, and its default value is 1.

    • Receive processing: generally only accepts "untagged" ordinary Ethernet MAC frames, and "tags" the frame according to the PVID of the interface receiving the frame, that is, inserts a 4-byte VLAN tag field. The VID value in the VLAN tag field is the PVID value of the interface.

    • Forwarding processing: if the VID value in the frame is equal to the PVID value of the interface, the frame is "untagged" before being forwarded; otherwise, the frame is not forwarded. Therefore, frames forwarded from an Access interface are ordinary Ethernet MAC frames without VLAN tags.

  • Trunk interface: generally used for interconnection between switches.

    • This interface can belong to multiple VLANs, that is, it can pass frames belonging to different VLANs.

    • The default PVID value is 1, and users are generally not advised to modify it; if the PVID values of interconnected Trunk interfaces are not equal, forwarding errors may occur.

    • Receive processing: it can receive both "untagged" ordinary Ethernet MAC frames and "tagged" 802.1Q frames; if an ordinary Ethernet MAC frame is received, the frame is "tagged" according to the PVID of the interface receiving the frame, which is the same as the processing of an Access interface.

    • Forwarding processing: for an 802.1Q frame whose VID value is equal to the PVID value of the interface, it is "untagged" and forwarded; for an 802.1Q frame whose VID value is not equal to the PVID value of the interface, it is forwarded directly. Therefore, frames forwarded from a Trunk interface may be ordinary Ethernet MAC frames or 802.1Q frames.

  • Hybrid interface: an interface type proprietary to Huawei switches.

    • It can be used both for interconnection between switches (the same as a Trunk interface) and for interconnection between a switch and user computers (the same as an Access interface).

    • In addition, most functions of a Hybrid interface are the same as those of a Trunk interface. The difference lies in the forwarding processing of a Hybrid interface: a Hybrid interface checks whether the VID value of the frame is in the interface's "untagging" list. If it is present, the frame is "untagged" and then forwarded; if it is not present, the frame is forwarded directly.

In addition, VLAN division can also be based on MAC addresses or network-layer protocols.

7 802.11 Wireless Local Area Network

7.1 Composition

With the development of mobile communication technology, wireless local area networks (WLANs) have gradually entered the market since the late 1980s. In 1997, IEEE formulated the protocol standard 802.11 for wireless local area networks. This is one of the most widely used wireless local area networks, and people more commonly refer to it simply as Wi-Fi (wireless fidelity).

802.11 wireless local area networks can be divided into the following two categories:

  1. Those with fixed infrastructure
  • Basic Service Set (BSS): Communication between stations within a BSS, as well as communication with stations outside the BSS, must be forwarded through the access point (AP) within the BSS. Network administrators need to assign the AP a service set identifier (SSID) of up to 32 bytes and a wireless communication channel; the SSID is actually the name of the 802.11 wireless local area network using that AP.
  • Extended Service Set (ESS)
  • The 802.11 standard does not define specific methods for implementing roaming; it only defines the following basic services. Association service: There are two methods for a mobile station to establish an association with an AP: passive scanning and active scanning. Beacon frame: Contains parameters such as the SSID, the AP's MAC address, supported rates, encryption algorithms, and security configurations.

Reassociation service and dissociation service: If a mobile station wants to transfer its association with one AP to another AP, it can use the reassociation service; if it wants to terminate the association service, it should use the dissociation service.

  1. Those without fixed infrastructure: ad hoc networks

  • Forwarding stations need to have routing functionality.

  • Ad hoc networks are easy to set up, do not require base stations, and have very good survivability, which gives ad hoc networks good application prospects in both military and civilian fields.

  • The ad hoc mode of 802.11 wireless local area networks allows stations in the network to communicate directly within their communication range, that is, it supports single-hop communication between stations, while the standard does not include multi-hop routing functionality, so this mode is rarely used.

7.2 Physical Layer

The physical layer of 802.11 wireless LANs is very complex. It can be divided into multiple physical layer standards based on operating frequency band, modulation method, transmission rate, and so on.

802.11 wireless network cards are generally made multimode so that they can adapt to a variety of different physical layer standards.

Wireless LANs initially also used infrared (IR) technology and frequency hopping spread spectrum (FHSS) technology, but these are rarely used now.

7.3 CSMA/CA Protocol

Wireless LANs use another protocol called CSMA/CA, namely Carrier Sense Multiple Access/Collision Avoidance. Compared with CSMA/CD, the protocol only changes collision detection to collision avoidance; however, it cannot actually avoid all collisions, but rather minimizes the probability of collisions.

Reasons for not using collision detection

  • Because the transmission environment of wireless channels is complex and the dynamic range of signal strength is very large, the signal strength received on an 802.11 wireless network card is generally far smaller than the strength of the transmitted signal, and the signal strength may even differ by a million times; therefore, if collision detection were to be implemented on an 802.11 wireless network card, the hardware requirements would be very high.

  • Even if the collision detection function could be implemented in hardware, due to the particularity of radio wave propagation (the hidden station problem), there would still be cases in which collisions cannot be detected, so implementing collision detection is meaningless.

Basic working principles of the CSMA/CA protocol:

  • DCF (distributed coordination function)

    • The length of the interframe space DIFS is 128 μs, used for sending data frames and management frames.

    • In DCF mode, there is no central control station, and each station uses the CSMA/CA protocol to obtain the right to transmit by contending for the channel.

    • It is the default mode defined by 802.11 (mandatory to implement).

    • Waiting for the DIFS interval takes into account that other stations may have high-priority frames to send.

  • Virtual carrier sense mechanism

    • The value of the "Duration" field in the frame header indicates the time the source station wants to occupy the channel (including the time required for the destination station to send back an acknowledgment frame).

    • When a station detects the "Duration" field in the header of a frame being transmitted on the channel, it adjusts its own network allocation vector (NAV); the NAV indicates the time required to complete the transmission of this frame and for the channel to transition to the idle state.

  • The length of the short interframe space (SIFS) is 28 μs. It is the shortest interframe space and is used to separate frames belonging to one dialogue.

    • A station should be able to switch from transmit mode to receive mode within this time.

    • Frame types that use SIFS include ACK frames, CTS frames, and so on.

  • Because the bit error rate of wireless channels is relatively high, the CSMA/CA protocol also needs to use a stop-and-wait acknowledgment mechanism to achieve reliable transmission (this is different from shared Ethernet using the CSMA/CD protocol).

Backoff algorithm:

  • When a station wants to send a data frame, the backoff algorithm is not used only in this case: the channel is detected as idle, and the data frame is not a data frame sent immediately and continuously after the previous data frame was successfully sent.

  • In all other cases, the backoff algorithm must be used: when the channel is detected as busy before sending a frame; when retransmitting a frame each time; and when continuously sending the next frame after each successful frame transmission.

  • When executing the backoff algorithm, the station sets a random backoff time for the backoff timer: when the backoff timer decreases to zero, it starts sending data; when the backoff timer has not yet decreased to zero and the channel becomes busy again, it freezes the value of the backoff timer, waits again for the channel to become idle, and after DIFS, continues to start the backoff timer.

  • During the iiith backoff, the backoff time is randomly selected from the slot numbers {0,1,…,22+i−1}\{0, 1, \dots, 2^{2+i} - 1\}{0,1,…,22+i−1}, and then multiplied by the basic backoff time (that is, the length of one slot) to obtain the random backoff time; when the slot number reaches 255 (corresponding to the 6th backoff), it no longer increases.

To further reduce the probability of collisions, 802.11 wireless LANs allow the source station to reserve the channel.

  • The RTS (request to send) frame is a short control frame. It includes the source address, the destination address, and the duration required for this communication (including the time required for the destination station to send back an acknowledgment frame).

  • The CTS (clear to send) frame is a short response control frame. It also includes the duration required for this communication (this duration is copied from the RTS frame into the CTS frame).

  • Stations other than the source station and destination station defer access to the channel after receiving the CTS frame or data frame, thus ensuring that the communication between the source station and destination station will not be interfered with by other stations.

  • If an RTS frame collides, the source station cannot receive the CTS frame, and the source station will execute the backoff algorithm to retransmit the RTS.

  • Using RTS frames and CTS frames for channel reservation brings additional overhead; however, since RTS frames and CTS frames are both very short, the probability of collision, the overhead caused by collision, and their own overhead are all small. For ordinary data frames, their transmission delay is often much greater than the propagation delay (because it is a local area network), so the probability of collision is high, and once a collision occurs and causes the data frame to be retransmitted, a lot of time is wasted. Therefore, reserving the channel at a very small cost is often worthwhile.

  • Nevertheless, 802.11 wireless LANs still provide users with the following three choices: use RTS frames and CTS frames; use RTS frames and CTS frames only when the length of the data frame exceeds a certain value; do not use RTS frames and CTS frames.

  • Since RTS frames and CTS frames both carry the duration required for communication, this is the same as the virtual carrier sense mechanism described earlier in which data frames can carry the duration required for communication. Therefore, using RTS frames and CTS frames for channel reservation also belongs to the virtual carrier sense mechanism. With the virtual carrier sense mechanism, as long as a station overhears any one of a data frame, RTS frame, or CTS frame, it can know the duration for which the channel will be occupied without needing to actually sense the signal on the channel. Therefore, the virtual carrier sense mechanism can reduce the collision problem caused by hidden stations.

7.4 MAC Frame

MAC frames are divided into:

  • Data frames: used to transmit data between stations

  • Control frames: usually used together with data frames, responsible for clearing the area, maintaining virtual carrier sensing, and channel access, and acknowledging upon receipt of data frames. ACK frames, RTS frames, and CTS frames all belong to control frames.

  • Management frames: used to join or leave a wireless network, and to handle connection transfers between APs. Beacon frames, association request frames, and authentication frames all belong to management frames.

Data frame format:

  • Duration: used to implement the virtual carrier sensing and channel reservation mechanism of CSMA/CA; in data frames, RTS frames, and CTS frames, this field indicates the duration for which the channel will be continuously occupied.

  • Sequence control: used to implement reliable transmission in 802.11 by numbering data frames.

  • The four address fields depend on the values of the two fields "To DS" (to the distribution system) and "From DS" (from the distribution system) in the frame control field.
