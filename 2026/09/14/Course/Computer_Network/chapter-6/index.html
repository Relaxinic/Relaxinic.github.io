The application layer is the top layer of the network architecture. It represents the ultimate purpose of designing and building computer networks and is the fastest-developing part of networking. Applications have developed from early text-based e-mail, remote login, file transfer, and newsgroups to the Web that brought Internet access into homes in the 1990s, followed by instant messaging, P2P file sharing, and audio/video applications. Smaller, ubiquitous computing devices and rapidly expanding residential broadband and wireless access provide opportunities for further applications.

Other application-layer protocols to recognize include:

  • SSH, Secure Shell, and Telnet, teletype over the network, for remote login.

  • RTP, Real-time Transport Protocol, for real-time data such as audio and video. It uses UDP.

1 Application-Process Communication Models

When developing a network application, the first consideration is how its programs are organized across end systems and how they relate to one another. The main models are client/server, peer-to-peer, and browser/server.

1.1 Client/Server (C/S)

Client and server refer to the two communicating application processes: the client requests a service and the server provides it. The server remains running and waits for requests. It has a fixed port number, such as HTTP's default port 80, and its host has a fixed IP address.

Server processes can operate in two ways:

  • Iterative mode: one service process runs at a time, responding to requests in arrival order in a blocking manner.

  • Concurrent mode: multiple service processes run simultaneously, each responding to a particular client, allowing concurrent rather than sequential service.

C/S is the traditional and most mature Internet model, used by the Web, e-mail, FTP, and many other applications. Its services are centralized on far fewer servers than there are clients. A server may fail to keep up with numerous client requests, so a computer cluster or server farm is often used to construct a powerful virtual server.

1.2 Peer-to-Peer (P2P)

P2P has no fixed requester or provider. Processes on end systems at the network edge are peers that communicate directly, each both requesting and providing services. Applications include P2P file sharing, instant messaging, P2P streaming, and distributed storage.

Services are decentralized across many peer computers rather than concentrated on a few servers. These computers are usually individually controlled desktops and laptops in homes, campuses, or offices, rather than machines owned by the service provider. A prominent characteristic is scalability: adding a peer adds both demand and service capacity, so system performance does not decrease as its scale grows. P2P also has a cost advantage because it generally requires neither a large server installation nor large server bandwidth, attracting providers seeking to reduce costs.

3 Domain Name System (DNS)

In 1983, the Internet began using a hierarchical naming tree for host names, or domain names, together with the distributed Domain Name System (DNS). Most names can be resolved locally, and only some resolutions require Internet communication, improving efficiency. Its distributed design means that one computer's failure does not prevent the entire system from operating. DNS mainly uses UDP, although it also uses TCP in some situations.

3.1 Domain-Name Structure

Internet domain names form a hierarchical tree.

A name consists of components separated by dots, representing successive levels:

... .third-level-domain.second-level-domain.top-level-domain

Each component contains letters and digits, has at most 63 characters, and is case-insensitive. The lowest level is written at the left and the top level at the right. A complete name is no longer than 255 characters.

DNS specifies neither how many subordinate domains a domain must contain nor what each level must mean. Each level is managed by the authority for its parent domain, while ICANN manages the top level.

Top-level domains (TLDs) have three categories:

  • Country-code domains, following ISO 3166, such as cn for China, us for the United States, and uk for the United Kingdom.

  • Generic domains: com for businesses, net for network-service organizations, org for nonprofit organizations, int for international organizations, edu for educational institutions, gov for government departments, and mil for military departments.

  • The reverse domain arpa: used for reverse resolution from IP addresses to domain names.

Each country determines its own second-level domains below its country-code TLD. For example, Japan uses ac and co for academic and commercial organizations under jp, rather than edu and com.

China divides second-level domains into two categories:

  • Category domains: ac for research institutions, com for industrial, commercial, and financial enterprises, edu for educational institutions, gov for government, net for network-service organizations, mil for military organizations, and org for nonprofit organizations.

  • Administrative-region domains: 34 domains for provinces, autonomous regions, and municipalities, such as bj for Beijing, sh for Shanghai, and js for Jiangsu.

3.2 Name Servers

Mappings between domain names and IP addresses are stored in name servers for other applications to query. All information cannot be stored on one server, so DNS distributes it across servers in different locations.

Root name servers occupy the highest level and know the names and IP addresses of all TLD servers. Although commonly described as 13 root servers, each is actually implemented by a cluster of computers distributed worldwide. A query from a local name server can be routed to a nearby root-server instance, accelerating resolution and using Internet resources more efficiently. A root server normally returns the relevant TLD server's IP address rather than directly resolving the complete name.

TLD name servers manage the second-level domains registered under their TLD. Their responses may give the final result or the IP address of a lower-level authoritative server.

Authoritative name servers manage names within a zone. Every host name must be registered with an authoritative server, which knows the relevant name-to-address mappings and the addresses of subordinate name servers.

A local name server, sometimes called a default name server, is not part of this hierarchy. A host sends its DNS request to the local server first. The local server acts as a proxy and forwards queries into the hierarchy. An ISP, university, or even a department may operate one. It is usually only a few routers away or on the same LAN, and its IP address must be configured on hosts requiring name resolution.

Because recursion places a heavy load on queried servers, the usual arrangement is a recursive query from the requesting host to its local name server, followed by iterative queries for the remaining resolution steps.

Name servers widely use caches to store recently resolved names and records of where their mappings were obtained. This improves efficiency, reduces load on root servers, and reduces DNS traffic. Because mappings may change, each cached item needs an expiration timer and must be removed after a reasonable period, such as two days.

User hosts also need caches of recently used names and should query a server only when the cache does not contain the name. Many hosts download the complete database of domain names and IP addresses from the local name server at startup and maintain caches of recently used names. Hosts must likewise keep cached information valid.

3.4 DNS Resource Records (RRs)

  • SOA, Start of Authority: specifies authoritative information for a zone, including its primary name server, administrator's e-mail address, serial number, and zone-refresh timers.

  • A, address: returns a 32-bit IPv4 address.

  • AAAA: returns a 128-bit IPv6 address.

  • MX, mail exchanger: directs a domain to its list of message transfer agents (MTAs).

  • CNAME, canonical name: gives a host-name alias; DNS continues looking up the new name.

  • PTR, pointer: points to a canonical name and is commonly used in reverse DNS lookup.

  • NS, name server: identifies the name servers responsible for a zone.

  • SPF, Sender Policy Framework: encodes which machines in a domain send mail to the Internet, helping recipients check validity.

  • SRV, service: identifies a host providing a particular service in a domain; for example, the Web server for cs.washington.edu might be cockatoo.cs.washington.edu.

  • TXT, text: originally allowed a domain to identify itself with arbitrary text; it is now often used for machine-readable information, commonly SPF information.

4 File Transfer Protocol (FTP)

File transfer moves a file from one computer to another, potentially far away, over a network. File Transfer Protocol (FTP) is the most widely used Internet file-transfer protocol. It provides interactive access, lets clients specify file types and formats, and supports permissions, including authorization and a valid password.

FTP hides computer-system details, making it suitable for file transfer between heterogeneous systems. Depending on the application, an FTP server may need a high-performance, highly reliable server or only an ordinary PC. Typical uses include batch file transfers and uploading the files making up a website to its Web server.

  • Active mode: the FTP server initiates the connection to the client when establishing the data channel.
  • Passive mode: the FTP server waits for the client to initiate the data connection.

5 E-mail

E-mail was one of the earliest popular Internet applications and remains an important, practical application. An e-mail system uses the client/server model and has three main components:

  • User agent: the interface between the user and the mail system, also called e-mail client software.

  • Mail server: the infrastructure that sends and receives mail and maintains user mailboxes. Internet ISPs provide mail servers.

  • Protocols: sending protocols such as SMTP and reading protocols such as POP3 and IMAP.

5.2 E-mail Message Format

The message format is not defined by SMTP. It was separately specified in RFC 822 and updated by RFC 5322 in 2008. An e-mail consists of an envelope and content; the content consists of a header and a body.

5.3 Multipurpose Internet Mail Extensions (MIME)

Basic SMTP carries ASCII text, not executable files or other binary objects. It cannot directly support multimedia messages containing pictures, audio, or video, or many non-English writing systems, including Chinese, Russian, and accented French or German.

Multipurpose Internet Mail Extensions (MIME) addresses this limitation.

  • It adds five mail-header fields describing the message body.

  • It defines content formats and standardizes multimedia-mail representation.

  • It defines transfer encodings that convert content without allowing the mail system to alter it.

MIME is used not only with SMTP but also with the later ASCII-oriented HTTP protocol.

5.4 Common Mail-Reading Protocols

Post Office Protocol (POP) uses port 110. POP3, its third version, is an Internet standard. It is a simple protocol with limited functions: users download messages and either delete them from the server or leave copies. It does not let users organize server-side mail through operations such as creating folders and classifying messages.

Internet Message Access Protocol (IMAP) uses port 143. IMAP4, its fourth version, is described as a proposed Internet standard. It is more powerful than POP3 and lets users manipulate server mailboxes as though they were local. It is therefore an online protocol.

5.5 Web-Based E-mail

Users can log in to a mail server's website with a username and password to compose, send, receive, read, and manage mail. This resembles IMAP operation, but requires only a general-purpose browser rather than a dedicated user agent. Mail websites usually provide powerful, convenient management functions without requiring messages to be downloaded for local organization.

6 World Wide Web

The World Wide Web (WWW) is not a special computer network. It is a large online information repository and a distributed application running on the Internet. Hyperlinks connect pages on different websites into a logical information network. Tim Berners-Lee at CERN first proposed it in March 1989.

The graphical browser Mosaic appeared in February 1993, and Netscape Navigator was released in 1995. Common browsers include Chrome, Firefox, Safari, and Opera. The rendering engine, also called the browser engine, parses and displays content. Different engines may render the same page differently, so authors need to test pages with different engines.

6.2 Web Documents

HTML, Hypertext Markup Language, uses tags to describe a page's structure and content.

CSS, Cascading Style Sheets, describes its visual style.

JavaScript is a scripting language, distinct from Java, that controls page behavior.

6.3 Hypertext Transfer Protocol (HTTP)

Hypertext Transfer Protocol (HTTP) defines how a browser, acting as a Web client, requests documents and how a Web server returns them.

HTTP/1.0 uses nonpersistent connections. Each file request establishes a TCP connection and closes it after the response. Each document incurs 2RTT2\mathrm{RTT}2RTT of overhead; if a page references many objects, each object needs this additional time. Browsers reduce delay by opening parallel TCP connections, but this consumes server resources and can impose a heavy burden when many clients are served.

HTTP/1.1 uses persistent connections. The server keeps the connection open after a response so the same client can send further requests and receive responses over it. This applies to documents on the same server, not only objects referenced by the same page. Pipelining further improves efficiency: the browser can send several requests before receiving their responses, and the server returns responses in sequence. This saves RTTs, reduces idle connection time, and improves downloading efficiency.

HTTP messages are text-oriented. Fields are ASCII strings of variable length.

6.4 Using Cookies to Record Information

Early Web applications simply displayed static documents from different servers, so HTTP was designed to be stateless to simplify server design. More complex applications, such as online shopping and e-commerce, require servers to recognize users. Cookies let servers remember users without requiring them to provide an identifier explicitly on every interaction, adding state to otherwise stateless HTTP.

6.5 Web Caches and Proxy Servers

Caching improves Web efficiency. A Web cache may reside on a client or an intermediate system; an intermediate cache is also called a proxy server. It temporarily stores recent requests and responses on local disk. If a new request matches a cached request, it returns the stored response instead of accessing the resource again through its URL. A high cache-hit rate greatly reduces link traffic and Internet-access delay.

6.6 Content Delivery Network (CDN)

The content delivery or distribution network (CDN) concept arose from MIT's work on flash crowds in Web services in 1998. It is a Web caching system that serves content near the network edge and users. Its services have expanded to include static content, streaming media, user-uploaded video, and more.

Its main advantages are:

  • Lower response delay and less network congestion.

  • Reduced origin-server overload and protection against DDoS attacks.

  • A distributed architecture with good scalability.

  • Transparency to users.

Providers include dedicated CDN companies such as Akamai, ChinaCache, 21Vianet, and Wangsu; Internet content providers such as Tencent and Baidu; and ISPs such as China Mobile, China Unicom, and China Telecom.

Key design questions are where to deploy servers, where and what to cache, and how to redirect requests to nearby or less-loaded servers. Clients obtain content from nearby CDN nodes or caches, allowing a Web service to support more clients.
