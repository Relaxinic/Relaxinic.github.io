Chapter 1 Overview

1.1 Internet

Network: formed by interconnecting several links and nodes.

Internet: formed by interconnecting several networks through routers, a network of networks.

The Internet is the largest internet in the world. The Internet has developed into a multi-level interconnected network based on Internet Service Providers (ISPs).

1.2 Network instance

Network edge

End systems: computers and other devices located at the edge of the Internet and connected to the Internet.

End systems are composed of various hosts: clients (desktop computers, mobile computers, and various other smart terminal devices) and servers.

Functions of hosts: to contain (i.e., run) applications, generate information and send data to the access network, and receive data from the network and provide it to applications.

Access network

  • Goal: to connect hosts to edge routers.

  • Edge routers are the first routers on the path from an end-system host to any other remote end system. Various heterogeneous networks access through edge routers.

  • Connection forms between end systems and edge routers:

    • Wired network access technologies: fiber to the home FTTH, Ethernet, coaxial cable, twisted-pair DSL, and the ancient dial-up Internet access.

    • Wireless network access technologies: WiFi, 4G/5G, and satellite wide-area coverage.

Network core

A mesh network composed of packet-switching devices and communication links of interconnected end systems

Composed of packet switches (routers, link-layer switches) and communication links (fiber optics, copper cables, radio, laser links)

Two major functions:

  • Routing (Global operations): determining the path used by data packets from source to destination. Requires routing protocols and routing algorithms, and produces a routing table.

  • Forwarding (Local operation): a router or switch forwards received data packets onward (i.e., moves them to a certain output interface of the device). Determining the output interface/link to forward to: based on the destination address in the packet header received from the “input interface,” look up the local routing table to determine the “output interface.”

1.3 Circuit switching, packet switching, and message switching

Circuit switching

Data transmission between computers is bursty in nature. When circuit switching is used to transmit computer data, the transmission efficiency of the line is generally very low, and the time actually used on the line to transmit data is often less than 10% or even 1%.

Establish connection (allocate communication resources) - Call (continuously occupy communication resources) - Release connection (return communication resources)

Packet switching

Sender: construct and send packets

Switching nodes: cache and forward packets

Receiver: receive packets and restore the message

Advantages:

  • There is no process of establishing a connection and releasing a connection

  • During packet transmission, communication links are occupied segment by segment, resulting in higher communication line utilization

  • Switching nodes can independently select a forwarding route for each packet, giving the network very good survivability

Disadvantages:

  • The packet header brings additional transmission overhead

  • Store-and-forward processing of packets by switching nodes causes a certain delay

  • It cannot ensure that all end-to-end communication resources are available during communication, and network congestion may occur when traffic is heavy

  • Packets may experience problems such as out-of-order delivery and loss

Message switching

The predecessor of packet switching. The entire message is sent, rather than being split into several packets for transmission. A switching node can only look up the forwarding table after receiving the entire message, and then forward the entire message to the next node. Therefore, compared with packet switching, the forwarding delay is much longer, and the cache space required by the switching node is also much larger.

If a large amount of data needs to be transmitted continuously, and the data transmission time is much greater than the time required to establish a connection, then using circuit switching can achieve relatively high transmission efficiency; however, computer data transmission is often bursty, so when circuit switching is used, the utilization rate of the communication line will be very low.

Neither message switching nor packet switching requires establishing a connection in advance (that is, preallocating communication resources), so when transmitting bursty computer data, they can improve the utilization rate of the communication line.

Dividing a message into several smaller packets for packet switching results in lower delay than performing message switching on the entire message, and it can also avoid an overly long message occupying the link for a long time, which is beneficial to error control and also provides greater flexibility.

1.4 Definition and Classification

A computer network is mainly composed of some general-purpose, programmable hardware interconnected together, and this hardware is not specifically designed to achieve a particular purpose (for example, transmitting data or video signals). This programmable hardware can be used to transmit many different types of data and can support a wide range of and ever-growing applications.

Programmable hardware: not limited to computers, but also includes smart hardware such as smartphones, sensors with network capabilities, and smart home appliances; these hardware devices must contain a CPU.
Various applications: various applications implemented based on data transmission, including various applications that may appear in the future.

Classification:

  • Switching method: circuit / message / packet switching (see the previous section)

  • Users: public network: the Internet; private network: military, railway, electric power, banking

  • Transmission medium: wired network / wireless network

Coverage range:

  • Wide Area Network (WAN): tens to thousands of kilometers

  • Metropolitan Area Network (MAN): 5-50 km

  • Local Area Network (LAN): ~1 km

  • Personal Area Network (PAN): 10 m

Topology: bus / star / ring / mesh

1.5 Performance Metrics

Rate: The transmission rate of data (i.e., how many bits are transmitted per second), also known as data rate or bit rate.

  • The basic unit is bits per second (bit/s, which can be abbreviated as b/s, and is sometimes also written as bps (bit per second)).

  • Commonly used units (note the unit conversions):

    • Kilobits per second (kb/s or kbps) = 10^3 bps

    • Megabits per second (Mb/s or Mbps) = 10^6 bps

    • Gigabits per second (Gb/s or Gbps) = 10^9 bps

    • Terabits per second (Tb/s or Tbps) = 10^12 bps

Bandwidth: refers to the capability of a network’s communication line to transmit data, that is, the maximum data rate that can pass from one point in the network to another per unit time.

  • Unit: same as “rate”

  • Data transmission rate = min[host interface rate, line bandwidth, switch or router interface rate] (short-board effect)

Throughput: the actual amount of data passing through a network or interface per unit time. It is often used to measure an actual network in order to determine exactly how much data has passed through the network. It is limited by network bandwidth.

Delay/latency: the time consumed for data to be transmitted from one end of the network to the other, also called delay or latency.

  • Data may consist of one or more packets, or even a single bit.

  • Transmission latency (also called transmission delay) = packet length (b) / transmission rate (b/s) (for the transmission rate formula, see the “bandwidth” section)

  • Propagation latency = channel length (m) / signal propagation rate (m/s)

  • Queueing latency and processing latency are inconvenient to calculate.

  • Total latency is the sum of the above four latencies.

Bandwidth-delay product = propagation delay * bandwidth, also called the length of the link in bits, which is very helpful for us to understand the minimum frame length of Ethernet later.

Round-trip time (RTT): the total time elapsed from when the sender starts sending a data packet to when the sender receives the corresponding acknowledgment packet sent back by the receiver.

Utilization

  • Link utilization: the percentage of time a link is utilized (that is, data is passing through it); the utilization of a completely idle link is zero.

  • Network utilization: the weighted average of the link utilizations of all links in the network.

  • According to queueing theory, when the utilization of a link increases, the delay caused by that link increases rapidly.

  • When the network traffic is relatively low, the resulting delay is not large, but as network traffic continues to increase, the queueing delay of packets in switching nodes (routers or switches) will increase accordingly, so the delay caused by the network will increase.

  • Some large ISPs often control channel utilization to no more than 50%; if it exceeds that, they expand capacity by increasing the bandwidth of the line.

Packet loss rate: The ratio of the number of packets lost during transmission to the total number of packets within a certain time range.

  • Divided into interface / node / link / path / network packet loss rate.

  • Packet loss mainly occurs in the following two situations:

    • A packet has a bit error during transmission and is discarded after a node switch (such as a router) or the destination host in the transmission path detects the bit error.

    • A node switch actively discards packets according to a discard policy.

  • The packet loss rate can reflect the congestion situation of the network: when there is no congestion, the path packet loss rate is 0; when there is mild congestion, the path packet loss rate is 1% ~ 4%; when there is severe congestion, the path packet loss rate is 5% ~ 15%.

1.6 Architecture

Two communication modes:

  • Connectionless service: No need to establish a connection in advance

  • Connection-oriented service: Also called virtual circuit service; a virtual circuit must be established before communication

The OSI (open system interconnection) model allows the network layer to support two modes: connectionless (IP) + connection-oriented (X.25 and other protocols)

In the TCP/IP model, the network layer (IP layer) is connectionless, and connection-oriented functionality is implemented by the transport layer (TCP)

The TCP/IP architecture is shown in the figure:

Entity: Addresses the problem of implementing specific network applications through the interaction of application processes.

Peer entities: Entities at the same layer on both communicating sides.

Protocol: A set of rules that controls two peer entities in performing “logical communication” in the “horizontal direction.”

  • Three elements of a protocol:

    • Syntax: Defines the format of the information exchanged.

    • Semantics: Defines the operations to be completed by both communicating sides.

    • Synchronization: Defines the timing relationship between both communicating sides.

  • The data packets transmitted between peer layers are called the protocol data unit (PDU) of that layer.

Service:

  • Protocols are “horizontal,” while services are “vertical.”

  • An entity can see the services provided by the lower layer, but does not know the specific protocol that implements the service; the lower-layer protocol is “transparent” to the upper-layer entity.

  • The logical interface through which entities in two adjacent layers in the same system exchange information is called a service access point (SAP), and it is used to distinguish different types of services.

  • The “type” field of a frame, the “protocol” field of an IP datagram, and the “port number” field of a TCP segment or UDP user datagram are all SAPs.

  • For the upper layer to use the services provided by the lower layer, it must exchange some commands with the lower layer, and these commands are called service primitives.

  • The data packets exchanged between layers within the same system are called service data units (SDUs).
